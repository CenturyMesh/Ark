# 020B — direct dimensions and agent DFM

Runtime `0.9.21`, principal phase B. The iteration addresses A.01, B.01,
B.02, B.03, C.03 and D.04. These milestones remain **Parcial** beyond the
bounded local checks below. The `.ark` document version is unchanged.

## Human authoring

**Drag extrude** turns a saved closed sketch into an isolated exact native
candidate. Pointer movement updates its depth, release publishes one validated
feature, Tab accepts an expression, and Esc leaves the document intact. The
original extrusion `cap.end` can be pushed or pulled while preserving its
source sketch and starting cap. Double-clicking a visible solid opens its
authored scalar dimensions and expressions; selecting a row edits the source.
The agent's `doc_apply` path uses the same parameters and driving sketch
dimensions with an observed `expected_revision`.

The gesture and overlay contract, screenshots from synthetic fixtures and
scoped checks are in [viewport dimensions](../VIEWPORT_DIMENSIONS.md) and the
[dimension verification record](../verification-direct-dimensions.json).
Supported source families, dependency behavior and multi-feature workflows
remain narrower than the complete B.01/B.02/B.03 acceptance criteria.

## Process screening for agents

`manufacturing_inspect` now returns `components[].dfm` with versioned rules,
exact producer evidence where available, explicit caller assumptions and typed
recommendations for laser, bend, FDM, CNC and weld planning. The report does
not mutate a document or certify manufacture. Agents can use a recommendation
to propose a revision-checked design or process change. The [DFM contract](../DFM.md)
and [DFM verification record](../verification-dfm-2026-10-13.json) distinguish
caller arithmetic, exact geometry comparisons and unresolved process evidence.
C.03 remains **Parcial** pending actual machine, slicer/CAM, material and pilot
evidence.
