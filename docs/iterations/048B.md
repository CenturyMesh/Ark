## Parametric HUD (B.01, B.02, D.02)

The request was a design whose dimensions the human can change while ARK
rebuilds the model, with edits coming from an agent or from the human. The
mechanism is named parameters with optional HUD metadata:
`param.set{name,expr?,hud?:{label,min,max,step,unit,group,order}|null}`.

**Agent protocol** (`agent_onboard{topic:"hud"}`), used only when the user
asks:
1. Declare the driving parameters first.
2. Write every driven dimension as an expression of those parameters.
3. Run the read-only `hud_flex_check` and fix failures.
4. Report `hud_info`.

**Range checks.** An agent value outside the HUD range rejects with
`HUD_VALUE_OUT_OF_RANGE`; ARK never clamps it. In Studio, the HUD overlay
stages human edits and publishes them in one human `doc_apply` on Rebuild, or
publishes each edit with Auto. A failed rebuild leaves the revision intact and
shows the error.

**Flex check.** `hud_flex_check` evaluates min, mid and max per parameter on a
scratch copy. It is evidence for the sampled values only, not for the whole
range or for combinations.

See [Parametric HUD](../PARAMETRIC_HUD_048B.md).

## Exploded views and Visualize (B.04, B.05, D.04)

**Exploded views.**
- `explode.set`, `explode.rename` and `explode.remove` author named exploded
  views as ordered translation steps of assembly instances.
- The views are persisted, revision-checked and undoable.
- The factor 0..1 drives display transforms only. B-rep, mates and placements
  never move, and the factor never changes the revision.

**Link to the animation skeleton.** A motion-graph channel without `mate` may
set `explode_view`, so baked motions animate the explosion together with the
joints.

**Visualize.**
- The Studio panel renders the assembly, exploded or at a motion time, with
  the existing GPU path tracer or the raster fallback.
- It can add balloons and a BOM table, and exports PNG.
- Agents use the read-only `explode_info` (with `propose`) and
  `visualize_render`, and only on an explicit user request, the same rule as
  for drawings.
- Renders show display tessellation and never authorize geometry.

See [exploded views and Visualize](../EXPLODED_VISUALIZE_048B.md).

## Integration changes

- **Studio action ids.** Both features had picked the 47000 range. The HUD now
  uses 48000–48999; exploded views keep 47000–47399.
- **Tool count.** The tool catalogue grows from 102 to 106. The eight
  exact-count tests assert 106.
- **Team scope.** `explode.*` commands join the orchestrator's assembly-level
  team scope, alongside `motion.*`.
- **`query_batch`.** It accepts `explode_info` and `hud_info`. `hud_flex_check`
  and `visualize_render` stay direct calls because they evaluate or render.

## Limits

- **Flex check** samples three values per parameter, one parameter at a time.
- **HUD dependency inventory** is lexical. It does not follow assembly
  placement expressions or indirect native-spec references.
- **Exploded steps** are translations only. The 2D drawing workspace does not
  show exploded states.
- **Visualize export** in GPU mode is at viewport pixels; larger presets are
  upscaled. Software renders are capped at 1920x1080.
- **Visual quality** was judged on synthetic fixtures only.
