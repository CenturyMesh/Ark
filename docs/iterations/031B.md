# 031B — Advanced modeling and agent contracts

Runtime identity is generated from `release.json`. This development iteration
extends the 030D base. The verification below records local evidence before PR
integration; it does not establish a published package or manufacturing
qualification. No private drawing or agent session is a regression fixture.

New tools retain editable history and explicit source dependencies. Exact OCCT
geometry and triangle authority remain distinct. Invalid geometry, undefined
continuity/law domains, exhausted diagnostic capacity and inconsistent mates
reject without silently increasing tolerances, dropping parts or substituting
meshes. All persisted authoring still uses observed `expected_revision` and
atomic publication. Focused remains the default and Parallel stays optional.

[Explicit candidate refresh](../CANDIDATE_REFRESH_031B.md) addresses A.03/D.02/D.04
for independent agent proposals. Ordinary commits retain bounded prepared
recipes; the owner can explicitly refresh an unchanged supported dependency
scope at the observed current revision, inspect its new IDs and then commit.
Old apply payloads still reject. Targets, transitive dependencies, document
context, role ownership and project boundaries remain guarded. This does not
establish measured provider token savings or arbitrary transaction merging.

The [evaluation and persistence work](../PERFORMANCE_031B.md) adds audited
incremental dependencies, canonical history validation reuse, native phase
profiling and a bounded Windows result cache. Binary container v2 optionally
carries evaluated native OCCT B-rep and topology alongside the complete editable
authoring history, without inserting STEP files or display meshes. It still
reads earlier containers and keeps authored source-format selection independent.
Saved geometry is validated on matching native requests; unsupported or changed
requests rebuild. Opening with a local result cache, validating document-carried
geometry and replaying all modeling instructions remain different workloads.
No five-second cold-open or full-rebuild threshold is established by these tests.

The bounded domains are explicit in the module contracts. In particular,
variable-radius fillets initially accept one straight semantic edge; continuous
twist/scale sweep laws initially accept a straight single-edge spine; G1/G2 and
extension geometry checks disclose their measured support/checkpoint scope;
mesh deviation is sampled rather than a universal Hausdorff bound; assembly
sweeps check the requested poses rather than the trajectory between them.

Local Windows Release verification on 2026-10-16 passed **123/123 native**
CTest cases in 108.33 seconds and **80/80 portable-core** cases in 28.76 seconds.
Coverage includes solids, surfaces, meshes, contracts, assembly sweep,
incremental evaluation, binary persistence/migration, native profiling/cache
and saved geometry validation. The saved-state native suite contains 112
checks. Document custody regressions cover dependent result restoration,
parallel feature workers, failed candidates and isolation between documents.
Candidate refresh tests cover independent recipes, exact OCCT volumes, peer
geometry ownership, implicit datum ancestors, replacement versus append import,
same-role team receipts, injected recipes and unsupported cumulative edits.
The native build includes Studio, MCP and the pinned OCCT worker in an isolated
runtime output directory to preserve the open user session; live Studio
desktop tests were not enabled. Suite durations are verification records,
not matched application performance measurements.

The first full native run passed 114/116. One older test still treated newly
supported source43 as a future format; it now checks source44. The updater test
encountered a Windows atomic replacement error, then passed two isolated runs
and the complete final run without updater code changes. Earlier geometry
failures and their fixes are retained in the module records and
[verification receipt](../verification-031B.json), together with source/binary
hashes. These are local synthetic checks, not deployment, continuous geometry
certification or manufacturing qualification. Existing broader roadmap
milestones remain **Parcial** until their own acceptance evidence exists.
