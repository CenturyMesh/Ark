# 012D — agent activity, request size and CAD responsiveness

Runtime `0.9.13`, baseline `011E` / `e0a1d81`. Milestones
A.01/A.03/A.04/B.01/D.01/D.02/D.04.

## Changes

- Dependency cache keys follow referenced sketches, ordinary datum planes and
  evaluated parameters. Unrelated authoring no longer invalidates every exact
  solid. Geometric supports and projections retain conservative dependencies.
- Appearance-only transactions and previews avoid copying evaluated bodies;
  prepared candidates remain valid when only usage/audit records change.
- Repeated native centroid queries use a B-rep digest cache. Native shape
  reports compute the same exact volume once rather than twice. Numerical
  integration, tolerance, semantic references and atomic acceptance remain
  authoritative.
- Windows snapshots use lossless compressed PNG. Request projection accounts
  for schemas and the actual ChatGPT byte limit, omitting older image pixels
  when necessary while retaining the original history and semantic metadata.
  Oversized human text is still explicitly rejected, never silently truncated.
- Live draft events include new datum planes and parameters. Busy presentation
  displays role and feature progress while retaining the committed scene.
- Persistent measured action records and mandatory subjective tool ratings,
  including issues and requested tools/options. See [activity contract](../AGENT_ACTIVITY.md).

## Evidence and limits

The native suite passed **65/65** in 108.81 s. Final targeted persistence,
assistant transport and activity tests passed **3/3** in 4.82 s. Regression
coverage includes unchanged solids after unrelated authoring, dependent-plane
invalidation, metadata rollback, preview reuse through usage changes,
activity ownership/immutability, SQLite reopen, undo, required feedback,
lossless pixel equality and real noisy PNG requests exceeding 4 MiB.

Verification found an old v27 history assertion (agent audit now requires
v33) and offline UI expectations that omitted the new feedback round; their
fixtures were corrected. A build overlapped a still-running test executable
and hit LNK1104; the build was rerun after the test finished. This was a build
artifact lock, not a user application restart.

The final assistant UI (17.062 s), startup UI (3.203 s) and render UI
(2.359 s) passed with isolated settings and synthetic documents. Captures
were inspected for a sketch on a newly authored parameterized datum, the
busy panel and the read-only activity report. The render fixture now uses
a geometry-affecting command to exercise the worker: a material-only command
correctly bypasses that path. The busy capture proves message pumping and
the committed scene remain visible; it does not prove every provider emits
fine-grained authoring steps. The activity report's misleading generic editor
caption was corrected to an actual read-only control.

Local timings compare frozen private inputs with identical operations on the
same machine. Private drawings, identifiers, geometry and raw measurements
are excluded from tracked evidence and packages. These timings do not compare
Single versus Focused/Parallel model quality, cost or task acceptance.

D.01 remains **Parcial**. The 009B pilot remains closed at nine attempts,
one accepted; no additional live pilot was run. A.04, B.01, D.02 and D.04
remain **Parcial** beyond the measured local regressions. Cold freeform
geometry can still be expensive; no claim that all kernel work is subsecond.
Model reasoning is not a stream of sketch edits. The implementation displays
received tool steps and preserves atomic publication rather than exposing
unvalidated native geometry. The external adapter remains pending.

and no `.ark` files. All five executables match the tested build; 64 installed

process was preserved, as were all 34 observed drawing hashes. The running
