## Claude diagnosis and reconnection

The reported interruption was reproduced with the installed Claude Code CLI
2.1.319, the selected model/effort and a synthetic read-only session. It loaded
no drawing and executed zero CAD tools. The SDK returned a `success` envelope
with `is_error:true`, `terminal_reason:api_error` and an expired OAuth-login
message. The old adapter discarded that reason, displaying `result success`.
The official CLI sign-in completed and the user confirmed normal operation.
No credential was edited, copied into a test receipt or stored by ARK.

The adapter now reports bounded categorical causes, including
`authentication_expired`, and retains safe failure metadata. A failed provider
result cannot declare the task complete or replay an earlier write. Successful
results retain their prior completion and revision checks. Host projection and
real CLI compaction require a fresh successful document inspection before
subsequent writes; exact read-reference deduplication does not cause unnecessary
inspection loops.

The selected connector labels the account button. **Claude Code → Reconnect
Claude Code…** launches the installed CLI's official interactive login, then
checks account and SDK metadata without inference. CAD and conversation state
remain retained. New assistant/team work is blocked while reconnection is in
progress; the task resumes only on a later human action. Cancellation affects
only the owned account subprocess, not the browser or user CAD processes.
Metadata-only checks cannot clear an observed expiry. External credential
overrides remain under their original owner's control.

[reconnect controls](../CLAUDE_RECONNECT_071D.md).

## RAM and worker selection

The previous256MiB value limited one extra parsed native-result cache, not
ARK's total RAM or Claude Code's memory. That cache now scales with detected
RAM and available memory. Healthy16/32/64GiB machines target1/2/4GiB of decoded
results and256/512/1024MiB of worker snapshots. These are demand-only ceilings,
not allocations or guarantees on total process working set.

On the observed24-core/32-thread machine with63.77GiB visible RAM, targets were
**4081MiB decoded /1020MiB snapshots**, and the hardware worker ceiling was
**16**. Actual dirty work, estimated graph width, CPU allowance and memory
pressure can lower it. An explicit ceiling of32 is supported on this machine;
hundreds of pending tasks do not require hundreds of simultaneously executing
CPU workers. Serial and narrow chains retain their full native allowance.

| Matched synthetic workload | Smaller configuration | Larger configuration |
|---|---:|---:|
| 96native operations/32independent branches, native result cache off |4workers:626ms|Auto16:304ms|
| Same uncached branches |16workers:286ms|32workers:232ms|
| Same work with budget-specific caches preseeded |16workers:131ms|32workers:129ms|
| 36exact-sphere working set, repeated rebuilds |256MiB:19.90ms|Auto:6.35ms|

The RAM comparison retained **365.56MiB**, not the full4GiB ceiling, and used
about101MiB more owned-process private commit than the smaller cache. The old
allowance produced72 measured reparses and no decoded hits; Auto produced72hits
and no reparses. One and four deep chains showed no meaningful speedup from
requesting16 rather than4 workers, and retained the correct1/4 actual width
and native allowance8. Twenty-four workers did not beat16 in the uncached wide
fixture. More workers therefore remains a workload-dependent option.

Across the comparisons,9,657 numeric geometry properties and72 sphere
volume/bounds pairs matched, with no failed final measured operations.
Idle native processes and their hidden consoles are reported separately from
peak active feature jobs; process count is not a concurrency measurement.
Full receipts and caveats: [resource policy](../RESOURCE_POLICY_071D.md),
`out/performance-071d/resource-comparison.json`.

After the final authentication/UI relink, final-byte rechecks recorded
359.3ms for the wide Auto16 workload and5.65ms for the RAM workload, with
the same32 terminal geometry records and72 decoded hits/zero misses. These
repeat observations remain separate from the matched comparison above; timings
vary with machine activity. Final runtime hashes are in the recheck receipts.

## Verification and scope

Initial focused resource, scheduler, Claude/ACP, native RAM and reconnect
contracts passed. Policy checks include low/unknown RAM, pressure, overrides,
scaled cache capacity and serial/native graph correctness. Claude checks include
17 terminal-failure cases, preserved receipts, no replay/private-provider-text
leakage, successful completion and compaction recovery. The account controller
uses offline process/probe seams and an owned native status fixture.

The authentication recovery observed on the installed CLI is distinct from the
offline controller/UI tests. No live design task was run as a test.

Final validation passed **196/196 native/script suites**, **7/7 affected Studio
suites**, and **2/2 final normal/compact conversation rechecks**. The account
controller passed25 native checks; resource policy passed1,074 and the scheduler
7,812. The actual Win32 account menus, selected-connector button, readable
expiry/reconnection messages and disabled controls were visually inspected.
User drawings and original conversation receipts remained outside the fixtures.

The first menu capture attempt read desktop pixels and was rejected during
inspection. Its replacement renders the owned popup through `PrintWindow`/
`WM_PRINT`, verifies glyph pixels, and combines actual GL/native application
controls. One premature test invocation while the linker still held Studio was
not run; it is retained separately from the completed successful validation.
Receipts are under `out/release-068B/`, including `native-071d-final.xml`,
`ui-071d-final.xml` and the final targeted development-build receipt.

No agent turn/token budget, automatic provider switch or paid API fallback was
added. More local RAM/workers cannot renew a provider credential or enlarge a
remote model's context window. Geometry authority, tolerance, expected revision,
atomic publication and existing user sessions remain protected.
