# 064A — continuous manipulation and GPU key-light shadows

Technical version: **0.9.65**. Focus: **A**. Milestones: **A.02, A.04,
B.01, B.04**. **Verificado no escopo local**; broader milestones remain **Parcial**.

- **A.02/A.04/B.04:** a component drag owns an immutable manipulation baseline.
  Fixed continuation intervals retain validated checkpoints separately in each
  direction. Reversing or revisiting a coordinate uses the same original path;
  it does not rebase authored geometry. The final interval still checks mate
  residuals, limits, rank, branch continuity and coupling axes. Cache storage is
  bounded to 8 MiB of estimated pose data per direction; exhaustion continues
  solving normally. Release/cancel discards the path; publication still checks
  the original document revision.
- **A.04/B.01:** opaque display geometry casts key-light shadows into a 2048²
  float32 depth map on the GPU. Filtered visibility attenuates the direct key
  light, including occluders outside the camera image. Transparent bodies receive
  shadows but do not cast opaque silhouettes. No CPU ray-scene rebuild or new
  geometry upload is required for rigid movement.
- **B.01:** local horizon occlusion replaces noisy projected-hemisphere samples
  and screen-space shadow rays. Stratified radial phases and bilateral filtering
  address sampling bands. This remains an approximate ambient cue; the key-light
  map is not ray-traced soft lighting or transparent shadow transport.
- **A.04:** continuous input cannot indefinitely postpone presentation. Visible
  rendering uses swap-interval pacing without an additional Windows timer sleep.
  Minimized/invisible windows retain a bounded idle delay.

## Verification scope

**16 focused suites passed in 30.73 seconds**: release metadata, manipulation
performance, mechanisms, joint limits, normal/compact section inspection,
navigation, assistant revision/steering, transmission, viewport capture,
asynchronous authoring, realtime interaction, scene-cache reuse, viewport
quality and interaction controls. GPU tests verify float32 shadow storage,
caster movement/restoration without mesh uploads, graphics Apply/Cancel/input
validation/persistence and unchanged authored geometry. Close-up, synthetic
lighting and section captures were inspected.

On the RTX 4070 Ti, the synthetic three-body quality fixture at 1440×900 took
0.711 ms median / 0.742 ms p95 for a completed frame with high-quality FXAA.
This is a local fixture measurement, not a guarantee for arbitrary assemblies
or an end-to-end display-latency measurement.

The mechanism tests compare cached and uncached poses through forward motion,
rewinds, direction changes, joint limits, multiple revolutions, rack-and-pinion,
cam and closed-linkage motion. A changed caller program cannot replace the
baseline owned by an existing path. Existing tolerances remain unchanged.

The local `--profile-viewport` diagnostic reads a configuration and a loaded
document, measures stationary, orbit and actual mouse-message joint-drag frames,
and verifies unchanged authored source/revision. Completed CPU+GPU frame timings
use `glFinish` only in the diagnostic; they exclude monitor/compositor latency.
Private drawings, captures and profiles stay outside public evidence.

Initial visual review rejected the first deterministic AO sampling because it
produced radial bands; those samples were refined before final verification.
Broader roadmap milestones remain **Parcial**. No OTA release or manufacturing
qualification is implied.

## Feature-tree follow-up and PR validation boundary

The Model tab now uses a floating, rounded panel at 66% opacity, category-coloured
duotone icons, segmented tabs, orange selection, count chips and subdued hidden
or suppressed rows. Datum visibility icons and the scrollbar were restyled.
The grid and solids are rendered behind the panel with a continued camera
projection; that additional strip omits AO and edge rendering. Layers and
Properties retain their existing presentation.

The contributing agent reported that the final translucent-tree version compiled
and was inspected in captures. The earlier opaque variant passed tree/general
UI checks. Its broader Studio run reported 77/81 passing: two team-blocker tests
failed, the assistant UI crashed, and studio-live could not run because its
executable was not built. Their relation to the tree changes was not established.
The 16-suite evidence above predates this tree follow-up and does not validate
the combined final revision. At the user's explicit request, no new build or
tests were run while preparing the PR; these outstanding results are retained
for review.
