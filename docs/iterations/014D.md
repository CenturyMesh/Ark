# 014D — visible BOM and enforced completion review

Runtime `0.9.15`, baseline `013B` / `3b23a3c`. Milestones A.01/A.03/B.05/D.02/E.01.

**Manage → BOM**, **Inspect → BOM** and All tools open a native table with
part numbers, descriptions, quantities, materials, make/buy, missing fields,
commercial references and source URLs. Refresh captures a new revision;
Edit part and Sourcing edit the selected definition and all its occurrences.
Existing metadata is retained; material names must refer to document materials.
Edits and exports reject stale snapshots. Export JSON uses the existing atomic
`ark.bom.v1` exporter, never overwrites a file, and publishes nothing remotely.
Review exposes the complete snapshot, document issues and unplaced definitions.

`bom_review` requires inspection of every BOM item page at the current revision
and authoring digest, plus internal part numbers/descriptions on every counted
physical definition. Subsequent edits invalidate the receipt. Empty drawings
do not create fictitious BOM obligations.

- Detailed scope rejects unresolved metadata: resolve with evidence or report
  needs_input rather than inventing materials, references or suppliers.
- Concept scope requires explicit pending_notes when incomplete. The host adds
  a concept/incomplete qualification to the visible completion.
- fastening_review describes inspected connections, missing hardware or justified
  non-applicability. Zero fasteners is neither automatically wrong nor proof of
  completeness. This remains a declared review, not a geometric hardware proof.

Production Studio Single holds its final reply until the host check passes.
Team blocks the lead's completed goal report; intermediate task handoffs and
needs_input remain available. Offline fixture transports use explicit test
orchestration; dedicated regressions exercise the host completion hooks.
External MCP clients receive bom_review but control their own final prose.
The host cannot enforce another application's UI or infer requested scope
reliably by parsing arbitrary natural language. It labels the declared scope;
agents are instructed never to downgrade an explicitly detailed deliverable.

Single retains interrupted history and marks missing tool receipts as unknown,
preserving IDs rather than clearing prior evidence. Unknown execution must be
followed by inspection, never blind replay. Repeated unchanged BOM rejection
surfaces explicitly rather than looping. No turn/token budget is introduced.
