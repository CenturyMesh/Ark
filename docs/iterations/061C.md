# 061C — mechanical mate engineering and transmission design

Runtime **0.9.62**, from `release.json`. Milestones
**A.02/B.04/C.04/D.02/E.01 — verified in local scope**; broader B.04/C.04 remain
**Parcial**. This development tree also retains the 060C manufacturing work.

The new native suite shares authored expressions with the existing mechanical
mate solver. It adds belt couplings, reference gear/chain/pulley sizing, selected
power-path analysis, shaft shear/twist, explicit double-helical load sharing and
bounded one/two-stage tooth/module/form optimization. Candidate preparation
binds document parameters and mates, then uses ordinary preview/apply. It does
not generate or qualify an arbitrary tooth profile. See
[contracts and assumptions](../TRANSMISSIONS_061C.md).

Extended mate fields and belt semantics require conditional document format 54.
Legacy kinematic mates retain their previous format. Reports stay derived;
revision/hash guards, geometric mates, undo/redo and source authority remain.

## Verification

Local Windows Release/MSVC builds succeeded. **14/14 focused suites passed**
(67.82 s in the recorded combined run). Focused coverage includes the new
transmission suite, assembly mates/mechanisms/joint limits, bicycle transmission,
agent catalog, context graph, document container, iteration history, release
metadata, mechanical motion, motion graphs/derived bakes and native Studio controls. The UI test exercises actual inspect,
analyze, mate-edit, optimization, selection and parameter-bound preview/apply
controls against a synthetic assembly. Its final offscreen panel capture was visually inspected.

Analytical comparisons cover gear pitch dimensions and power/force balance,
inverse module sizing, internal rotation, helical axial force, unequal
double-helical halves, distinct roller/timing pitch formulas, smaller-wrap
flat-belt grip, solid/hollow shaft torsion, source staleness, cancellation,
missing efficiency, branch power conservation, strict chain/belt length checks,
chain ripple/pull search constraints and standstill ambiguity.
Optimization tests compare compound reductions and both double-helical forms
under contact and axial-force constraints. Unknown/invalid inputs reject.

A native pilot reused the repository's bicycle source recipe. Through the
returned proposal and preview/apply, the front tooth pattern changed from 48 to
32 actual native solids. With 60 rpm and 10 Nm at the input, the output was
120 rpm and 4.75 Nm for a declared 0.95 chain efficiency and explicitly ideal
shaft. The resulting document was saved locally. This verifies parameter,
geometry and kinematic/load wiring; the existing illustrative sprocket recipe
is not a newly certified roller-tooth profile or tooth-contact result.

Retained development failures: a native UI test initially used mixed-type
`auto` declarations and was corrected; a zero-valued `double_helical` field was
incorrectly treated as enabled in an optimizer constraint and was corrected
with a negative helical/axial-force test. Hidden-window `PrintWindow` initially
produced a black image; the isolated test now renders offscreen without focus
activation and rejects an empty capture. No tolerance was widened to pass these
checks.
