# 058A — conversation layout after background progress

Technical version **0.9.59**, sourced from `release.json`. Milestones:
**A.02/A.04/D.02**. Status: **Verificado no escopo** in the local Windows
native build and inspected synthetic-fixture captures.

## Problem and scope

The 057B checks did not cover messages arriving while Studio was minimized.
Read-only inspection of the reported running 057B window found a response with
approximately 2,000 characters and 30 native display lines in a roughly
29,000-pixel-high child window (coordinates observed from a DPI-virtualized
probe). No private message text or drawing was collected into the fixture.

A standalone synthetic RichEdit probe reproduced the mechanism: while its root
window was minimized, resizing a newly populated 1-pixel control to 972 pixels
left 1,890 cached lines and a final-line position of 47,225. Restoring the window
can reflow the text without invalidating the application's cached bubble height.
`EM_REQUESTRESIZE` alone did not correct this in the probe. Setting the target
device back to the current screen width with `EM_SETTARGETDEVICE(NULL, 0)` did:
18 display lines and a final-line position of 425 for the same text and width.

The fix explicitly refreshes screen-width wrapping before reading native line
positions. It retains selectable text, complete message contents, native font
metrics and the outer conversation's reading anchor. This changes presentation,
not agent requests, execution, completion, document format or geometry.
When chat takes the whole workspace, the cube, triad, motion, appearance and grid
controls from the collapsed viewport no longer paint over its Single/Team row.

## Verification

The native conversation regression adds actual minimize/background-message/
restore transitions and compares the cached bubble height with the rendered
text. Existing selection, long-message, Unicode, goal, compact/wide and live
OpenGL/native-paint checks remain required. Tests use synthetic conversations
and separate settings, preserving the user's running session.

The strengthened Studio test reproduced the failure before the fix: a synthetic
2,188-character reply retained a cached height of **47,833** although its actual
19-line text measured **483**. Check 844 failed and the capture showed the blank
bubble. This failed attempt is retained in `out/058a-chat-baseline.log` and
`out/058a-chat-background-before.png`.

The existing 057B session was repaired without restarting it: a temporary narrow
window placement forced fresh measurement, then its original maximized placement
was restored. A second read-only bounds inspection found the same response's
native child at approximately **505** rather than **29,089** pixels high, with
the same character/line counts. This was a temporary layout recovery, not an
in-place binary upgrade; the minimized-window fix requires the new runtime.

The corrected runtime passed **12/12** selected suites in **34.00 seconds**:
release metadata/evidence, navigation, inertial UI, context, suspension,
normal/compact display bar, normal/compact assistant steering and normal/compact
conversation. `git diff --check` also passed. The build used Windows Release,
LLVM-MinGW 23.1.3, patched OCCT and an RTX 4070 Ti.

The background reply measured **483 cached / 483 actual** in the normal fixture
and **508 / 508** in the compact fixture. Three subsequent minimized updates
retained the same text control and selection. Both live captures found **700**
light glyph pixels in the final-line region after OpenGL swaps and native paint
dispatch. The before/fixed/live/expanded captures were inspected; the fixed
captures show the response end rather than an oversized blank tail. Expanded
chat also passes the assertion that cube/Home/appearance targets are absent.
Existing long reply, Unicode, reading-anchor, goal and Team checks passed.

Receipts are local in `out/058a-final-tests.log`,
`out/058a-native/Testing/Temporary/LastTest.log`, `out/058a-fixed-build.log` and
`out/058a-native/ui-checks`. These are synthetic lifecycle tests and a read-only
inspection plus layout recovery of the reported session, not general provider,
all-monitor-DPI or every chat-session qualification. Broader milestones remain
**Parcial**. No private drawing or conversation was added to the repository.
