# 015B — BOM workspace redesign and agent-feedback review

Runtime `0.9.16`, baseline `014D` / `ebda7ab`. Milestones
A.01/A.03/B.01/B.05/D.02.

The BOM is now a native dark workspace with clear totals, searchable parts,
All / Needs review / Buy / Make filters, two-line part rows, status badges
and a selected-part detail pane. Missing-field keys become actionable labels.
Part and sourcing editors, JSON export and the full evidence report retain
their existing revision checks. Filtered rows map to original definition IDs;
refresh and sorting preserve the selected definition where possible.
Locate part returns to the model; Copy link copies only the selected stored
source URL. No URL is fetched automatically. Existing native keyboard selection,
scrolling, Enter-to-edit and Ctrl+F search remain available.

The design is rendered directly with native controls and GDI, without generated
bitmap mockups or a browser dependency. Synthetic multi-row UI fixtures cover
search, incomplete-part filtering, minimum-width layout, editing a filtered
definition, export, unchanged read-only snapshots and completion review.
Screenshots at normal and compact sizes are inspected before delivery.

The private agent-feedback audit informs these follow-up priorities:

1. Typed resolution evidence for superseded failures: current errors are tracked
   by tool name, so a successful alternative inspection may not clear an older
   failure. Do not implement unconditional error clearing or suppress geometric
   validation failures.
2. Read-only library batching and better discovery of actual response fields.
   A rejected field projection should identify available fields rather than
   encourage guesses about names such as clearance or totals.
3. Profile one fixed expensive compound-clearance query before changing caches
   or native numerical algorithms. Summed host-call time is not provider time
   or total parallel elapsed time.
4. Reproduce the reported software-snapshot colour and closed-shell semantics
   separately. Agent self-reports are investigation leads, not geometric proof.

This iteration delivers the UI and records the analysis; it does not claim to
resolve those backend investigations. Raw project metadata, geometry, feedback
and timings remain in local ignored evidence. Subjective ratings alone do not
establish design quality, manufacturing readiness or cost savings. No live
pilot was added; the 009B pilot remains closed at 9 attempts / 1 accepted.
