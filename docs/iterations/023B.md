# 023B — exact CAD import, Holes Orchestrator and isolated design containers

Runtime `0.9.24`; phase B. `release.json` is the single identity source.
This branch follows the unmerged 022B draft and preserves its test preview.
Milestones A.01/A.03/A.04, B.01/B.02/B.03/B.04/B.05, C.01, D.02/D.03/D.04
and E.01 remain **Parcial** outside locally verified scope.

STEP/IGES files open through the CAD importer or file drop. The user chooses
**Just import** or **Arkitfy using agents**. Exact source bytes and transferred
geometry are embedded, including supported multiple solids and surface bodies.
Arkitfy prepares an explicit reconstruction task, invokes the configured agent
when available, and provides exact closed-solid comparison. Unknown feature
intent and unsupported surface equivalence remain explicit.

**Holes Orchestrator** provides local metric/inch hole and thread sizing, dowels
and retaining-ring groove recipes. Named locations and expression dimensions
remain editable features with source dependencies. Agents must use this workflow
for functional holes; sketch-only holes serve nonfunctional contours. The
catalog distinguishes published nominal data from caller-supplied values and
does not invent tolerance or manufacturing qualification.

Assembly groups also act as design containers. A scoped checkout copies its
editable closure and read-only dependencies into another `.ark`, suitable for an
independent ARK instance. Merge checks both the parent revision and source digest,
rejects boundary violations and preserves unrelated parent work. Source format
38 is conditional on these persisted features; the binary container format stays
unchanged. Existing logical document capacity remains bounded.

The repository was explicitly made private on 2026-10-14. At the user's subsequent
instruction, the existing Apache-2.0 license and dependency notices remain in
place. No license transition is part of this iteration.

## Verification and corrections

The first integrated Windows x64 Release build passed with LLVM-MinGW clang
23.1.3 UCRT and OCCT 8.0.1. All seven new core/Studio checks passed. The first
full run passed 112/115 in 201.33 seconds: three older discovery tests still
expected 86 tools instead of the implemented 90. Those assertions were updated;
the final full rerun passed **115/115 in 198.83 seconds**. Two subsequent
presentation-only adjustments shorten a clipped hint and use Windows multiline
line endings in the container review. Their affected Studio workflows are rerun
at 1440×900 and 1366×800. See [verification receipt](../verification-023B.json)
for final artifact hashes and the exact scope of the checks.
The compact command requested 1366×768, but Studio clamps height to 800; PNG
headers confirm 1366×800. A 768-pixel-high viewport was not verified.

Earlier tests exposed destructive recognition booleans modifying imported source,
an order-sensitive comparison of canonicalized census JSON, and a headless UI
fixture missing the real Assistant input. Recognition now uses non-destructive
booleans and preserves the original serialized transfer; census comparisons keep
field/type/value checks. The UI fixture now exercises the actual native input,
and Arkitfy opens the Assistant so its deferred task is visible. Exact source
hashes and geometric tolerances were retained.

Visual review also exposed a hierarchy presentation defect when an existing
occurrence was grouped under a newly appended container. The explorer now visits
parents before children without changing source order or IDs. Container tests
cover dependency-ordered merge, changed child source after review, preserved
outside source, read-only closure, stale parents and rejected invalid geometry.
Dialog capture targeting was corrected to inspect the actual dimension and merge
review pages, in addition to their first setup pages.

A cleared datum support initially survived container integration because an
omitted edit field retained the old value. The regression reproduced that error;
merge now emits explicit `support:null`. Unsupported removal of datum/placement
parameter keys or mate motion/limits rejects instead of silently retaining them.
Catalog-only performance evidence is 1,000 local M6 lookups in 10.0943 ms on this
run; it does not measure geometry or UI latency and is not a baseline speedup.

Manual user testing and merge approval remain pending; no broader manufacturing,
arbitrary-file-size or universal reverse-engineering qualification is claimed.
Thread flanks and automatic numeric fit-tolerance qualification are outside this
scope. Offline Arkitfy task staging does not prove live reconstruction quality.
See [manual testing](../AUTHORING_023B_TESTING.md).

Hosted CI [run 73](https://github.com/CenturyMesh/Ark/actions/runs/38560690377)
was rejected before job steps started. GitHub reports account payment or
spending-limit restrictions. This is not hosted test evidence; local results
above remain the available validation. No account spending settings were changed.
