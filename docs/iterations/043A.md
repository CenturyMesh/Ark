# 043A - faster document opening and rebuild

Runtime 0.9.44 and iteration identity come from `release.json`.
Milestone **A.04** remains **Parcial**. The changes below are **Verificado no
escopo local**: one private 74-feature freeform user document (not
distributed; only timings are recorded) and the regression suite. Three-size
p95 qualification of A.04 remains open.

Geometric authority, `expected_revision`, atomic publication and explicit
rejections are unchanged. No tolerance is relaxed, no solid is dropped and no
operation falls back to a display mesh.

## Diagnosis

Opening the document took 58-59 s with workers on performance cores and
98-111 s when ark-mcp was started from a background shell. Reading and staging
the file took 0.4 s; the embedded native geometry was restored, not replayed.
The time went to:

- display tessellation at a fixed 0.025 mm / 0.12 rad: 67% of worker time and
  4.2 million triangles;
- serial scheduling: one worker active for 47.5 of 58 s, while the measured
  critical path was 19.7 s;
- Windows EcoQoS throttling of windowless processes (about 1.8x);
- a 256 MiB first-in-first-out local cache, smaller than this document alone
  (222 MiB);
- on rebuild, multi-input booleans run as one worker round-trip per pair, each
  validated, measured and tessellated in full.

## Changes

1. **Display tessellation.** Parts up to a 250 mm diagonal keep 0.025 mm /
   0.12 rad. Larger parts use a chord deviation of 1e-4 of the diagonal (at
   most 0.5 mm) and 0.25 rad. This applies to generated and restored bodies.
   Picking edges follow the same deflection. The mesh stays non-authoritative.
2. **Scheduling.** The owner thread now hands its own audited explicit-input
   feature to the pool and keeps dispatching ready features whenever a job
   finishes, instead of blocking all scheduling while it evaluates. Job memory
   is charged by actual retained allocation; payloads are shared immutable
   storage, not a worst-case JSON mesh expansion. Publication stays in
   document order.
3. **EcoQoS.** Native workers, ark-mcp and Studio opt out of execution-speed
   throttling. This changes CPU scheduling and power use only.
4. **Local cache.** 2 GiB by default (`ARK_NATIVE_CACHE_MAX_MB`), at most 8192
   entries, least recently used eviction (a hit refreshes the entry). Deep
   cache directories use extended Windows paths; stores no longer fail
   silently beyond `MAX_PATH`.
5. **Boolean sequences.** A 2..16-input union, cut or common runs in one worker
   request. Each step uses the same OCCT operation and reference propagation as
   the pairwise `native_solid` request. Intermediates are checked in memory
   (valid B-rep, one positive-volume solid) and are not serialized, measured
   twice or tessellated. Only the final body is published through the same
   `finish()` contract. Errors name the failing step and tool namespace.
   Intermediate digest-bound handles, which were always obsolete in the final
   result, are no longer added to its topology.
6. **Duplicate measurement.** Body edits check their input with one volume
   integration and no second BRepCheck. Boolean tools are validated once.
   Thicken reuses the signed volume it measures for orientation.

## Measurements

Same document copy, same machine (i9-14900KF, 8 P-cores / 16 E-cores),
isolated `LOCALAPPDATA` per run, ark-mcp `doc_load`:

| Scenario | 0.9.43 (042D) | 0.9.44 (043A) |
|---|---|---|
| Cold open, started from a background shell | 104.8 / 105.3 / 110.6 s | 19.9 / 18.9 / 19.0 s |
| Cold open, pinned to performance cores | 58.3-59.5 s | 19.0 s |
| Second open, same build (70 cache hits) | 4.2-4.6 s | 2.5 s |
| Full rebuild, cache disabled, performance cores | 133.2 s | 48.2 s |
| Full rebuild, cache disabled, unpinned | not measured | 48.2 s |
| Local cache for this document | 222 MiB (largest 28.7 MB) | 73.8 MiB (largest 9.9 MB) |
| Features evaluated on the pool | 11 of 74 | 41 of 74 |

All runs restored 70 saved results with 0 rejections. The design digest
(per-feature state and exact bounds) is identical to 0.9.43 for all 74
features in every run, including the full rebuilds.

`native_cache_032d` compares the one-request boolean sequence with the
pairwise path: identical exact B-rep bytes and identical semantic references.

Studio, headless `--load` and `--shot` from a cold isolated profile: 101.2 s
on 0.9.43 and 20.1 s on 0.9.44. The two captures of the whole door are
visually identical. Studio reported 616 MB process memory and 77 MB VRAM
before, and 313 MB and 38 MB after. Close-ups of the hems were not inspected.

## Verification

Local Windows Release build against the verified patched OCCT 8.0.1 SDK, with
runtime identity 043A / 0.9.44: CTest **196/196 passed** in 432 s (serial), on
2026-10-19. `native-solid` now checks both tessellation regimes (0.025 mm for
a 143 mm diagonal, 1e-4 of the diagonal for 1414 mm). `native_cache_032d`
checks the one-request sequence against the pairwise path, a local hit and a
framed piece.

## Limits

- Meshes of hidden intermediate features are still generated; with the new
  tessellation they cost about a tenth of their former time. Deferring them
  until shown needs a viewer change.
- Restore still integrates GK volume at 1e-10 (about 12 s of worker CPU on
  this document); overlapping it with tessellation is not done.
- STL/OBJ export uses the display mesh, so exports of parts larger than a
  250 mm diagonal are coarser than before.
- The 30-second worker limit and the interference triangle budget are
  unchanged.
- Interactive Studio opening (window shown, user input) and GPU upload time
  were not profiled separately from the headless measurement.
- One document on one machine; not a three-size p95 qualification.
