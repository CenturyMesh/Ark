# 039D - persistent agent memory and Windows setup

Runtime 0.9.40 and iteration identity come from `release.json`.
Milestones **A.03/A.04/A.05/D.02/D.05/F.02/F.03/F.05** remain **Parcial**;
the native memory and resource-library contracts are **Verificado no escopo local**.

This iteration adds persistent, attributed local memory alongside the source
Graphify index, live CAD context graph and derived Obsidian views. The native
memory lifecycle has 133 passing checks for restart, project isolation,
concurrent processes, compare-and-swap revisions, expiry, explicit forget,
bounded retrieval, episodic promotion, feedback, consolidation, measured q4
compression and export. The pinned multilingual semantic provider performs
actual local inference, combined with literal FTS5 and attributed recency/feedback.
No paid provider is required for these local operations.

The official memXT binary was evaluated in isolation. Its supported glibc
runtime is absent from the available Linux environment, and its installer/CI
does not supply a native Windows build. The ARK implementation therefore uses
its existing native SQLite engine with a separately versioned local semantic
provider. No comparative memXT quality, speed, RAM or token-savings claim has
been established. Retrieved memories remain untrusted historical evidence;
current revision, B-rep and native inspection govern edits.

The independent reference compares all 512 components of four vectors, with a
maximum observed error of 5.96e-8. A fixed small retrieval pilot found the correct
record first for four English questions and two of three Portuguese questions;
the remaining Portuguese target ranked second. Measured q4 compression retained
those ranks and reduced the vector payload eightfold, with maximum cosine loss
0.0142651. This is not a universal quality or whole-database compression result.

An offline native CAD probe created a box, captured its scratch episode, then
explicitly promoted, indexed and semantically recalled it without changing the
CAD revision during memory maintenance. A separate memory-only MCP probe exercised
coding scope attribution, persistence and rejection of CAD calls. Startup recall
is a genuine tool-call/result pair, retains the original user request and treats
all remembered text as untrusted historical data. Full notes can be retrieved
explicitly; ordinary search and startup context remain bounded.

The Windows setup adds a branded welcome, destination selection and automatic
versioned installation. Existing launch, update and rollback contracts remain.
Isolated 038B payload tests passed installation, reinstall, uninstall and
preservation checks. A test initially replaced the desktop shortcut; it was
restored and isolated builds now exclude all real shortcuts. Actual wizard
screen capture was unavailable; generated artwork and control/layout evidence
are separate from a captured interactive wizard. Final 039D package, upgrade,
release publication and startup evidence is recorded separately when complete.

UI PNG resources are packed as original compressed bytes into `ark-ui.arklib`,
with a versioned index, ranges and SHA-256 per entry. The bundle is a resource
container, not a CAD format or component authority. This does not claim better
image compression. Malformed-input, integrity, byte roundtrip and deterministic
packaging checks pass. Final packed-only relocated UI and installer checks are
separate distribution gates.

The source graph and native-memory snapshot export into a new verified combined
Obsidian vault. Original source and personal vaults remain unchanged. A real
three-anchor export passed. Pointer publication uses an exclusive publisher lock,
bounded retries for observed transient replacement errors and preserves the prior
pointer on failure. Permanent errors remain explicit.
