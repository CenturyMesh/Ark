# 042D - fewer non-authoring agent rounds and stable request prefixes

Runtime 0.9.43 and iteration identity come from `release.json`.
Milestones **A.04/D.01/D.02/D.04/E.01** remain **Parcial**. The contracts below
are **Verificado no escopo local** by offline tests. No real-model A/B, cost
reduction or design-quality change is claimed for this iteration.

042D combines two merged changes: agent-loop, caching and live MCP repairs
([PR 24](https://github.com/CenturyMesh/Ark/pull/24)) and the agent tool layer
([PR 25](https://github.com/CenturyMesh/Ark/pull/25)). Geometric authority,
`expected_revision`, atomic publication and explicit rejections are unchanged.
No turn or token budget is introduced.

## Agent loops and completion (D.02, D.04)

- History projection now starts at 512 KB and keeps a 256 KB recency window,
  instead of starting at 96 KB. Early projection removed recent reads and
  caused repeated re-reads.
- Identical repeated reads carry a notice. Three repeat-only rounds add one
  plain developer note.
- Failed reads stay visible but no longer block completion by default. The
  strict 038D/041D contract remains available through
  `readFailuresBlockCompletion`.
- Specialist tools are advertised with their onboarding topic; proposal tools
  use shallow schemas.
- Responses requests may batch independent calls (`parallel_tool_calls`). The
  runtime still executes at most one document write per response.
- The Studio lead preloads the assembly guide. An unreviewed completion is
  answered once with a reviewer-checkpoint reminder.

## Tool layer (D.02, D.04, E.01)

Contracts are specified in [AGENT_TOOL_LAYER_042D.md](../AGENT_TOOL_LAYER_042D.md):

- `team_report_task` and `team_finish_goal` accept `ratings`, recorded through
  the role's audited executor after the report checks and before the report.
  Invalid or partial ratings reject with `unrated_activity_ids` and record
  nothing.
- A final reply held for missing ratings becomes final after a feedback-only
  round, without another provider round to repeat it.
- Lead handoff notices carry the role's report, committed steps, unresolved
  errors and observed revision.
- `query_batch` rows accept `id`, `{"$ref":"id.path"}` arguments, `paths` and
  `max_bytes`, with explicit row errors and `resolved_args`.
- `doc_info {detail:"digest"}` returns `ark.design-digest.v1` with per-object
  fingerprints; `known_fingerprints` returns only changed, new and removed
  objects. Fingerprints detect change only and never replace
  `expected_revision`.

## Providers and requests (A.04, D.01)

- ChatGPT plan requests carry no `prompt_cache_key`. In local development runs
  on the same brief and model, keyed requests reported 0 cached input tokens
  over 18 consecutive rounds; unkeyed requests reported cache hits from the
  third round. This is a provider caching observation, not a cost-saving claim.
- `ARK_ASSISTANT_TRACE` `provider_round` rows record provider, model, role,
  round kind, called tools and request byte composition. Rows from concurrent
  roles are written serially.
- Claude Messages keeps later host notes in place as `role:"system"` on the
  supported first-party models.
- Off-by-default A/B options: result handles with `result_get`, a stable
  projected prefix, a fixed tool list, a stable OpenAI cache key per role and
  deferred Claude tools surfaced with `tool_addition`. The Claude
  `tool_addition` request shape is tested offline only.
- DeepSeek preset. Provider API keys can be saved in Studio with current-user
  DPAPI, bound to the provider and endpoint host; see
  [CONNECTING.md](../CONNECTING.md).
- `studio.json` saves merge per key and replace atomically, so another Studio
  window no longer overwrites a connector saved elsewhere.

## Kernel and live MCP (A.04)

- Live MCP keeps the 30-second connect and transfer windows but waits up to
  10 minutes for the Studio result, instead of reporting an unknown outcome.
- Studio forwards progress as `notifications/progress` when a `tools/call`
  carries `_meta.progressToken`. The live pipe has four instances, so a second
  client queues during a long call. `ark-mcp --connect <pipe> --core-tools`
  lists core tools plus loaded topics and announces `tools.listChanged`.
- Centroids no longer compute inertia. Bounded Gauss integration is accepted
  only when its volume matches the Gauss-Kronrod volume within 1e-9; otherwise
  the full Gauss-Kronrod result is used. Worker time limits are reported as
  `RESOURCE_LIMIT`, not as a missing solid.
- CMake verifies the patched OCCT SDK unless `ARK_ALLOW_UNPATCHED_OCCT` is set
  for local diagnosis.

## Limits

- No real-model A/B was run. The procedure and primary metric are defined in
  [AGENT_TOOL_LAYER_042D.md](../AGENT_TOOL_LAYER_042D.md#ab-procedure).
- Concurrent reads against a revision snapshot are not implemented.
- The Claude `tool_addition` path has not been exercised against the live API.
- Unsigned Windows preview; clean-machine setup and internet update-feed
  delivery are not qualified.
- Private user drawings and histories are excluded from source, package and
  public verification artifacts.
