# 059C — rubber dynamics, exact surfacing and background GPU inspection

Technical version **0.9.60**, sourced from `release.json`. Milestones
**A.02/A.04/B.01/B.04/C.04/D.02**. Status: **Em curso**; verification pending.

## Implementation scope

- Exact editable `native_solid` operation `rubber_body`: belt/track racetrack,
  elliptical tire and solid/hollow ball. Numeric expressions remain authored
  parameters. Optional bounded exact relief fuses reusable motifs and rejects
  invalid/disconnected results atomically.
- Indexed procedural placement on cylinder, torus, sphere and racetrack,
  including circular, helical, chevron, braided and spherical distributions.
  Dense visual pebble/traction/chevron detail is distinct from exact geometry.
- Derived XPBD surface network, CPU reference and hardware D3D11 compute,
  ground/pulley contact, friction, explicit anchors and material inputs.
  Native CAD supplies total volume/mass. Link stiffness is a reduced model;
  it is not a calibrated continuum rubber or tire handling law.
- Agent `rubber_plan`, lazy rubber onboarding and parameterized command recipe.
- Native body click followed by Tab/Shift+Tab cycles exact canonical faces of
  the same occurrence while preserving editing/text-control precedence.
- GPU viewport snapshots use an owned framebuffer and the shared scene renderer,
  including bloom, occlusion and antialiasing, while Studio is minimized or the
  chat covers the viewport. Capture does not show, move or resize the window.
- Associative half-surface mirror with G0/G1 seam evidence; trim by a bounded
  surface, solid or exact open 3D wire with an explicit retained-region point;
  ruled surfaces between two exact single-edge rails; closed 3D-wire fills.
- Exact BSpline control-net inspection, bounded pole displacement and nearby
  exact vertex candidates for corner/tangent glue. Source/target hashes remain
  guarded; no sampled mesh positions become production geometry.
- Native forms for the surface workflows and control-net manipulation are being
  integrated. Guided patch fill with exact boundary supports is under validation.

## Acceptance and limits

Verify analytic native volumes, invalid-input rejection and atomic rollback,
recipe persistence, deterministic frames and bounded pattern paging, material
and mass authority, CPU/GPU solver agreement, anchors/contact/friction,
revision/cancellation guards, and inspect actual native UI captures.

No pressure/volume conservation, self-contact, fatigue, thermal coupling,
calibrated tire contact or manufacturing qualification is claimed. No runtime
speed advantage is claimed before equivalent measured comparisons. No change
to the `.ark` document version is required by the release identity.

Surface mirror checks continuity at the symmetry seam; it does not automatically
fair the input half. Trim retains one explicitly selected connected region and
accounts for removed regions. The cutter is finite. Pole edits preserve the
existing exact BSpline basis and reject unsupported trimmed, holed, closed,
periodic or solid inputs. Corner/tangent glue is not full-edge G1/G2 sewing.
Loft's internal continuity setting does not establish end-support tangency.

## Observed local evidence

- Patched OCCT native build, Windows, NVIDIA RTX 4070 Ti. No user drawing is used
  in the synthetic fixtures or included in this iteration's commits.
- Indexed pattern suite: 156,299 mathematical/contract checks, including a
  million-placement recipe with constant allocation and allocation-free indexed
  frame lookup. These are placement checks, not a million-solid benchmark.
- Rubber solver: 119 checks, CPU/GPU agreement, explicit anchors, contact,
  friction and link forces. For the same 256-node/930-link, 0.2 s study, measured
  CPU time was 3.24 ms and GPU time 14.38 ms; cached GPU run 13.86 ms. Maximum
  sampled difference was 4.12 micrometres. The second GPU run uploaded zero link
  bytes from the 29,760-byte constraint cache. GPU was slower for this workload.
  The separate integrated ball fixture (130 nodes, 720 links, 23 colours,
  48 steps, 8 iterations) measured CPU 3.04 ms and GPU 245.37 ms, with 9,312
  dispatches. These different fixtures must not be compared as a speedup.
- Native rubber authoring/preview/apply/persistence checks passed, as did the
  Rubber UI and real CPU/GPU engine UI tests. Creation, study and derived-frame
  captures were inspected. UI transport adversaries separately exercise stale
  revisions/epochs, cancellation, late callbacks and malformed frame payloads.
- Offscreen capture: 32 checks; hidden, minimized and expanded-chat captures
  produced identical pixels in the fixed fixture. Bloom changed 19,717 pixels.
  Window/camera/layout/document and framebuffer state were preserved, including
  a write failure after rendering. The GPU capture was visually inspected.
- Surfacing native tests initially passed 79 checks for mirror, cutter types,
  exact ruled rails and closed-wire fills; integration also passed source edits,
  dependency regeneration, save/reopen/recompute and atomic rejection.
- Media patterns, face cycling, native surface repair, direct authoring,
  viewport quality and assistant chat regressions passed. Actual pebble pattern
  and rubber-study captures were inspected.
- Failures retained in the development record: Windows `near` macro collided
  with native test helper names; JSON object-order comparison was corrected to
  compare canonical objects. Stock-preview face rejection initially reported
  visibility before preview mode. Sketch edit also failed on 058A because Fit
  placed an anchor behind the toolbar; the fit now reserves its actual height,
  and the sketch-edit, viewport-dock and viewport-quality regressions now pass.

Studio must remain running and connected for GPU snapshots. Named/custom views
still use their separate software path; this work does not make a disconnected
application available or remove the existing Visualize export UI restrictions.

## Technical sources

- [XPBD paper](https://matthias-research.github.io/pages/publications/XPBD.pdf):
  compliant position constraints and their relationship to energy.
- [Project Chrono tire models](https://api.projectchrono.org/development/wheeled_tire.html):
  distinguishes rigid, handling and deformable tire model scopes. ARK does not
  claim a Chrono integration or implement its calibrated tire models here.
- [GPU Gems procedural terrain](https://developer.nvidia.com/gpugems/gpugems3/part-i-geometry/chapter-1-generating-complex-procedural-terrains-using-gpu):
  procedural surface detail and triplanar texture blending as rendering techniques.

- [OCCT BSpline surface controls](https://occt3d.com/dev/doc/refman/html/class_geom___b_spline_surface.html):
  exact pole/weight editing within an existing spline basis.
- [OCCT constrained filling](https://occt3d.com/dev/doc/refman/html/class_b_rep_offset_a_p_i___make_filling.html):
  boundary support and internal curve constraints; ARK additionally checks its
  result and rejects unmet declared tolerances.

Final integration evidence is still being collected. The pattern combinations are ARK options, not a claim of
scientific novelty or state-of-the-art superiority.
