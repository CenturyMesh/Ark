# 081D — Context for follow-up edits

Runtime **0.9.82**, milestones **A.03/D.02**.

The request history projection measures the recent tool exchanges separately
from messages that it preserves in full. A large image between two inspections
can now travel with the detailed results of both inspections. The final
serialized request still has to fit the connector's byte limit.

A successful, identified `doc_info` row at the batch revision satisfies the
post-compaction inspection guard. An oversized sibling row includes a query
for recovering that row alone when its observed size fits the batch protocol.
Feedback on tool usage preserves detection of repeated identical design reads.
Single Assistant chat displays the provider round, the revision reported by
`doc_apply`, and the number of successful reads in a batch.

In a local comparison against 080D, both versions received the same 632,825-byte
synthetic history, including an inline PNG of 320,772 base64 bytes. Both sent
the image. Only 081D also retained the complete recent inspection in the
projected request. This comparison measures context retention. It does not
measure provider latency, model quality, or convergence on a CAD design.

Windows checks covered release metadata, the assistant connector, batched
queries, agent team, Studio steering, image attachment and two chat layouts.
The fixtures exercised partial success, revision mismatches, repeated reads
interleaved with feedback, and recovery of a single oversized row.
