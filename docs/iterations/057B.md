# 057B — conversation layout and viewport controls

Technical version **0.9.58**, sourced from `release.json`. Milestones:
**A.02/A.04/B.01/D.02**. Status: **Em curso** pending the local native build,
interaction checks and inspection of synthetic-fixture captures.

## Scope

The [conversation](../ASSISTANT_CONVERSATION.md) measures response height using
native text positions and font metrics. Latest lands on readable text, message
updates preserve selection and the reading anchor, and short split views retain
space for messages while the complete goal has its own scrollbar. Unchanged
frames no longer force a composer/header repaint.

The [orientation cube and display bar](../VIEW_CONTROLS_057B.md) use larger square
faces, shallow chamfers, face-aligned labels and a restrained blue hover. A
single toolbar groups explicit raster modes, overlays, projection, Fit,
selected-source drawing and further display options. Home has its own icon.

This iteration follows the locally integrated 056C runtime. Document geometry,
document format and agent completion/permission contracts are unchanged. The
validation uses synthetic fixtures, without user drawings or conversations.

## Evidence

Windows Release, LLVM-MinGW 23.1.3, patched OCCT 8.0.1, RTX 4070 Ti.

- The existing 056C conversation self-test passed. A strengthened test then
  reproduced a failure before the correction: Latest placed the final line of
  an 18,000-character response at y=-14, above the visible message page. The
  capture confirmed clipped text; retaining the full string was insufficient.
- After the correction, the new regression passed, including actual window
  pixels after 12 OpenGL swaps and the native message loop. Inspection confirmed
  visible final text and all four conversation actions. A capture taken before
  pumping native paint messages showed blank buttons; the live regression now
  dispatches those messages and checks both labels and backgrounds.
- Six integrated suites passed initially: camera contracts, cube navigation,
  normal/compact display bar and normal/compact conversation. Conversation checks
  include 1100/1180/1440/3556-wide layouts, selection during updates to current,
  earlier and later messages, more than 200 messages, goal scrolling, Latest,
  expanded view and Team states. Release metadata and evidence suites also pass.
- Navigation currently passes 208 face/edge/corner click-and-roll checks and 48
  cardinal label pixel checks. Geometry/font allocation remains retained; these
  are scoped observations, not a before/after speed claim.
- Source and capture review identified a further compact-layout issue: the cube
  became too small and the display bar could disappear with compact navigation
  and Assistant open. The shared layout correction and its regressions are in
  progress before final local runtime delivery.
