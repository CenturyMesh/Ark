# 041D - actionable read recovery and live team diagnostics

Runtime 0.9.42 and iteration identity come from `release.json`.
Milestones **A.03/A.04/D.02/D.04/D.05** remain **Parcial**. The guarded
read-recovery contracts are **Verificado no escopo local**; general autonomous
design quality and matched cost improvements remain separate acceptance gates.

Successful document, object, reference and batch reads now carry bounded
`team_progress` evidence and a concrete next action. Repeated coordination
evidence is identified separately from geometry: the actual native read remains
available and is not claimed unchanged by the coordination fingerprint. Pending
user input, Focused handoff, completed reports and required revision inspection
keep their scheduling priority. Repeated inventory queries are not design commits.

A later semantic reference can automatically supersede a failed planar-axis
selector only when the full producer-authored topology proves the original
unique selection predicate. The proof must belong to the same actor, subject,
project and current measured revision, after the failed occurrence. A compact
frame, a different face or ambiguous topology is insufficient. Other valid
same-subject corrections provide exact `team_report_task` arguments requiring
the author's explicit confirmation against design intent. Original rejections
and attributed resolution events are retained. Writes, previews, feedback and
completion gates cannot be waived by read supersession.

Core read identities remain strict when a host exposes a reduced tool catalogue
without `query_batch`. This boundary was exposed by the first isolated real-model
probe: the reduced harness accidentally selected legacy same-tool recovery. The
model created valid geometry, but that run failed the attributed-recovery
acceptance criterion and is retained as a failed attempt (12 provider requests,
334,196 tokens). Exact successful `find` queries now also support an explicit
author-confirmed correction; they do not fabricate a named-reference request.

Recovery receipts distinguish a failed native operation from a successful read
whose requested batch projection was invalid. They provide the actual target
and corrected read arguments, rather than another generic inventory request.
Large-history projection retains the latest bounded progress receipt as
historical data, with its revision and explicit authority limits.

`studio_team_diagnostics` is available only through `ark-mcp --connect` for
external diagnosis. It reports typed execution phase, active tool, measured
timing and bounded retained read evidence without entering the model tool
catalogue. It reads a mutex-protected team snapshot independently of the CAD/UI
queue. Team-observed revision is historical; an assistant phase alone does not
establish a network stall. Conversations, credentials and image payloads are
excluded, and omissions are explicit.

Local native recovery fixtures exercise author-confirmed named-reference and
`find` corrections, and topology-proven correction followed by a real atomic
feature edit. Each ends with one valid native solid of 720 mm3; final revisions
are 2 for the author-confirmed cases and 3 for the topology-proven case.
Negative cases preserve blockers for stale, mismatched, ambiguous, foreign and
unmeasured evidence. IPC checks cover actual connected Studio routing, read-only
arguments, active-tool diagnostics, bounded export and unchanged document state.
Final suite and real-provider evidence are recorded separately after execution.

A second isolated real-model task used the same synthetic prompt and reduced
ten-tool catalogue as the failed attempt, with `gpt-6.1-sol` and high reasoning.
The model authored its own read-resolution report; the host accepted it before
the sole geometry edit. Native validity, volume, BOM, feedback and explicit goal
completion passed at revision 2. This used 14 provider requests, 408,089 tokens
and 93.462 seconds. The two attempts consumed 742,285 tokens in total. This is
one Focused-role recovery task, not an open-ended multi-agent assembly benchmark;
it establishes the correction's behavior and does not establish token savings.

The broader Studio test run exposed existing Windows long-path limitations in
generated child-document/component artifacts and a relative example-file test
dependency. Short isolated artifact paths and the correct example working
directory are fixture controls, not evidence of product long-path support.
CTest's `ARK_STUDIO_TEST_ARTIFACT_ROOT` can select a short disposable directory;
the interaction fixture uses the source directory for its distributed example.
Original failures remain part of the verification record.

The combined memory/Obsidian workflow also exercises Graphify through a nested
PowerShell pipeline. Native extractor warnings remain visible diagnostic data;
they no longer become terminating PowerShell errors before the real process exit
code can be checked. Nonzero failures and source/anchor changes still reject the
export. A partially extracted graph remains navigation evidence, not proof that
an unreported symbol or dependency does not exist.

No agent turn/token budget, forced substitute geometry, tolerance relaxation or
silent rebase is introduced. Private user drawings and histories are excluded
from source, package and public verification artifacts.
