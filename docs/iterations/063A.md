# 063A — rigid movement, viewport shadows and section context

Technical version: **0.9.64**. Focus: **A**. Milestones: **A.02, A.04,
B.01, B.04**. **Verificado no escopo local**; broader milestones remain **Parcial**.

- **A.02/A.04/B.04:** rigid movement of audited local native solids retains
  evaluated geometry and solved sketches. Publication still validates assembly
  constraints, external sources and postconditions at the expected revision.
  Projected sketches, supported datums, occurrence consumers, unknown operations
  and mixed command batches retain the complete evaluation path. The native
  dependency cache also distinguishes a local saved sketch from occurrence poses.
- **A.02/A.04:** native mate frames and display topology use weak custody of
  immutable payloads. Repeated lookups no longer serialize topology or duplicate
  B-reps. Changed/expired owners invalidate the cache; verified lossless candidate
  compaction explicitly transfers custody. Unloading retains no geometry owners.
- **A.04/B.01:** drag previews use indexed placement lookup. The final preview
  stays visible during publication; failures restore the baseline. Ray tracing
  yields to the existing raster scene during component movement and private
  evaluation, then resumes progressive lighting at the final pose.
- **B.01:** right-click a construction plane in the tree, or a visible plane in
  the viewport, and choose **Create section view**. The selected plane defines
  the section directly. Existing Flip, Offset and Close controls remain available.
  Points, axes and coordinate frames do not offer a plane section.
- **B.01/A.04:** float32 linear depth removes half-float quantization from
  occlusion and contour sampling. Contact rays use 24 stratified steps and a
  smooth thickness window. Approximate ground cues use the visible world grid
  at Y=0; the backdrop no longer receives floating per-part shadow ellipses.

## Evidence and limits

**23 focused suites passed** in 36.73 seconds. Coverage includes native reference
invalidation (including a corrupt topology digest), unload/ownership, actual
occurrence-dependent geometry, stale revisions, prepared publication, undo/redo,
mate limits/mechanisms, persistence, normal/compact section controls and GPU
rendering. The native Studio worker test confirms that a prepared rigid drive
updates displayed poses without rebuilding meshes or uploading vertices again.
Section/menu and viewport captures were inspected.

The public `named-sketch-ring-revolute-v1` fixture uses the same commands and
native sources before/after, two warmups and ten measured commits, with history
disabled in both runs. Median core commit time was **6.276 ms → 0.096 ms**;
measured feature evaluations were **10 → 0**, with immutable geometry retained.
This is a local CPU comparison, not end-to-end input/display latency.

On the RTX 4070 Ti, at 1440×900, the same three-body synthetic quality fixture
measured **6.697 ms** median for rebuilding the ray scene at each pose versus
**0.718 ms** for interactive raster (completed `drawFrame` + `glFinish`, two
warmups, twelve measured poses). These modes have different lighting during
interaction; progressive ray lighting resumes afterward. Final stationary FXAA
HQ frames measured **0.672 ms** median versus **0.630 ms** in the earlier shader
run. No universal frame-rate, equal-lighting speedup or manufacturing claim is made.

Raw local receipts: `out/063a-final-tests.xml`, `out/063a-final-mate.json`,
`out/063a-final-quality.json`, and `out/063a-verification.json`. Private drawings
and their diagnostics are excluded from this public evidence and distribution.
One stale test assertion tying assembly tools to an obsolete global tool count
was replaced with checks for the unique command/preview endpoints. The separate
pre-existing broad assistant tool-count limit is outside this iteration's scope.

Screen-space contact shadows still cannot see hidden or offscreen occluders.
Progressive lighting after movement can still rebuild its world-space ray BVH
once; no per-instance acceleration structure or universal latency bound is claimed.
This iteration does not qualify manufacturing or publish an external CAD adapter.
