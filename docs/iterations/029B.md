# 029B — Trust and CAD authoring on the 028D foundation

`release.json` defines 029B / runtime 0.9.30, with principal phase B and addressed
milestones A.01–A.05 and B.01–B.05. The base is published 028D / 0.9.29,
commit `a96a7ed0ff8bd8ca6c9a58e0f6b9ec9739392bbb`. Application identity does not
change document format on its own. This work is developed separately from that
base; local verification does not imply a published release or hosted CI result.

The implementation keeps the 028D drawing vector and canonical source/occurrence
recipes, exact general CAD import, image/Stamp source, functional holes,
specialized patterns, design-container ownership, opaque validated previews,
local model selection and viewport dock. New authoring fields alone select
conditional source 40; scoped container v2 and orientation repair require 41.
A current rollback/load scope cannot resurrect inactive
geometry for drawing export or appearance validation. Restoring scope retains
the original bindings and checks staleness against the current exact producer.

`feature.move` rejects invalid dependency order and source-owned Skeleton moves.
`feature.rollback` retains authored IDs and downstream recipes. Creating/importing
definitions while rolled back requires explicit resume. Configurations apply
only their declared parameter/visibility fields; they do not silently restore
unspecified values. Selective loading retains full authored quantities and all
mate and pattern placement dependencies, following semantic source chains rather
than loading every unrelated definition. Unloaded derived caches are released.
Every external pin must match its imported producer metadata; loaded pins read
their producer files, deferred pins are reported and rechecked before reload.
Changed loaded bytes reject inspection/export and prepared publication.

Isolated v2 containers retain explicit configuration ownership and feature-owned
pins. Their load selection is workspace-local and cannot overwrite the parent.
Mixed-boundary recipes, readonly writes, global rollback and Skeleton boundaries
reject explicitly. Legacy v1 remains readable. Existing appearance/container
boundaries remain enforced. DXF and
other technical-drawing writes still require an explicit user drawing request.

An A.04 followup removes repeated history/loading scans and nested JSON copies
from `doc_info` while preserving its fields and output semantics. A matched
101-sample comparison at 16/128/512 features measured p95 query-time reductions
of 50.26%/56.09%/54.45% respectively. These are local synthetic API observations;
the initial regression, intermediate runs and broader qualification limits stay
recorded. The followup passed 70 core and 18 affected native/UI tests and produced
a separately verified local development ZIP. See the
[followup receipt](../verification/029B/doc-info-optimization.json).

The selected A.04/B.01–B.04 followup adds native viewport reuse, bounded
evaluation contexts, accessible/DPI-responsive forms, reviewed sketch repairs,
exact orientation repair and scoped container/configuration loading. Final
verification passed 71 core and 151 native/UI tests. The extracted development
payload passed 23 MCP calls, two Studio workflows and 144 native benchmark
attempts. A tangent-solver regression found by the first full run was corrected
before final qualification. See the [current verification](../VERIFICATION_029B.md)
and [consolidated receipt](../verification/029B/expanded-verification.json).
