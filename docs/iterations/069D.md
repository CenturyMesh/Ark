# 069D — Rebuild performance and reusable context

Technical version **0.9.70**, phase **D**. Addresses
**A.02/A.03/A.04/B.02/D.02/D.05 — Verificado no escopo local**. Broader roadmap
milestones remain **Parcial**; distribution evidence is recorded separately.

## Delivered behavior

- Successful exact sketch projections are reused within a recompute once all
  audited source dependencies have been published. Occurrence-dependent,
  failed, waiting and unknown closures stay conservative. Every new edit starts
  a fresh pass.
- `deform_poles`, `match_boundary`, `multi_trim` and `extend_trimmed` retain
  their exact results across unrelated earlier feature edits. Real input,
  expression or source-hash changes still reevaluate or explicitly reject.
- Outgoing requests share identical successful inspection evidence through
  direct references to complete earlier receipts in the same request. Host
  history, execution, revisions, errors and individual feedback remain intact.
- Persistent memory supports a short discovery index and reversible exact
  distillation of selected, revision-checked records. Outcomes, attribution,
  freshness and conflicting declarations remain distinct.
- Verified Obsidian exports include a recall index and a memory/code canvas
  with explicit source-anchor relationships.
- Targeted development builds reuse a configured directory, build selected
  executable/test targets, check configuration drift and record source/binary
  receipts. Scoped compiler parallelism and content-preserving asset preparation
  avoid needless serial compilation and timestamp churn.

## Measured local comparison

Synthetic models only, identical authoring inputs and commands on 068B and
069D. Seven samples per workload, first two warmup, medians of five measured
samples. Native result properties are compared independently of timing.

| Workload | 068B recompute | 069D recompute | Features evaluated before → after |
|---|---:|---:|---:|
| Unrelated edit, 42-feature/two-projection chain | 945.34 ms | 21.31 ms | 1 → 1 |
| Source radius edit, same chain | 984.15 ms | 26.76 ms | 2 → 2 |
| Unrelated edit, seven-feature surface fixture | 28.62 ms | 0.130 ms | 3 → 1 |
| Cutter expression edit, same surface fixture | 29.35 ms | 22.35 ms | 3 → 2 |
| Extension expression edit, same surface fixture | 7.40 ms | 7.38 ms | 1 → 1 |

The projection fixture makes four projection attempts, including two waiting
attempts, and reuses 84 later refreshes per pass. Forty before/after native
property comparisons agree, with zero failed benchmark operations. The extension
case shows no meaningful timing gain. These results do not establish equivalent
speedups for arbitrary drawings, offsets, assemblies or full cold builds.

Local receipts: `out/performance-069d/recompute-comparison.json`, the paired
projection/surface baseline and candidate receipts, and their output-only
reproduction scripts. The baseline runtime was recovered from the retained
068B package; its MCP/worker hashes match the recorded initial baseline.

In a repeated-content memory fixture, 12 full records total **43,528 bytes**;
the complete distillation receipt uses **15,537 bytes** and reconstructs every
record field. A single index receipt is **1,485 bytes** versus **4,098 bytes**
for the full read. Original stored content and revisions are unchanged.

Request-context metrics count serialized JSON, including a mixed conversation
with 24 reads, three writes and three failed reads: **512,369 → 281,039 bytes**
(45.15% reduction), with identical schemas, instructions and task, including
all writes and failures. The repeated-read history alone is **302,670 → 36,514
bytes**. The assistant suite passed **1,057 checks**, including reconstruction,
reference lifetime, metadata exclusion and provider-adapter contracts. These
numbers do not measure billed provider tokens, cost or model task quality.

The final targeted no-op build checked six executable targets in **4.173 s**
without C++ compilation or configuration. The complete invocation, including
four selected test suites, took **18.068 s**. Direct CLI no-op observations were
1.094 s before and 0.974 s after; these single observations do not establish a
compiler-speed gain. Pinned asset preparation rewrote two identical files before
and zero afterward, with essentially equal elapsed time. See the build document
for exact commands and receipts.

## Verification

The targeted integration passed four suites: projection/surface rebuild,
memory distillation, memory integration and assistant contracts. The new native
rebuild target checks analytic volumes/areas, exact B-reps/cache identity,
expressions, fresh reload, undo/redo, stale hash rejection and occurrence moves.

Initial validation caught two pre-delivery issues: the narrow index fallback
used the wrong representation fingerprint, and a test incorrectly rejected an
already present reference marker. The fallback now rejects an undersized index
bound and the exclusion test requires complete preservation of that receipt.
The final wire reference explicitly declares excluded per-call metadata fields
so reconstruction cannot inherit absent bookkeeping from an earlier call.

Final code verification: **190/190 non-Studio suites** and **8/8 affected Studio
suites** passed. The Studio selection covered assistant revision guards,
background authoring, realtime updates, parametric authoring, pole editing,
surface quality, surface operations and context controls. Captures of the native
authoring/model results were inspected. Receipts are
`out/release-068B/native-069d-final.xml` and `ui-069d-final.xml`; this existing
configured build directory was intentionally reused for 069D.

After the final assistant wire-contract change, the final runtime repeated both
geometry benchmarks with unchanged operation counts and zero failed attempts:
projection edits measured **23.95 / 27.27 ms**, surface unrelated/cutter/extension
edits **0.135 / 24.23 / 7.43 ms**. The final-runtime JSON receipts bind these
checks to the final MCP/worker hashes. The earlier paired comparison is retained
above rather than replacing its measured observations.

## Limits

No document semantic version change, tolerance increase, discarded-solid fallback
or silent rebase. No automatic memory promotion, inferred summary, conversation
ingestion or personal-vault mutation. Long-term memory remains untrusted
historical context and native B-rep remains geometric authority.

Large shared-header edits and Studio's large single translation unit can still
take significant compilation time. The targeted workflow avoids unrelated
build targets; it does not claim that one translation unit compiles faster.
No live-provider comparison, clean-machine certification, physical manufacturing
qualification, signing or hosted deployment is established here.
