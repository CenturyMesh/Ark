# 028D — Grok Build inside Assistant/Team and open chat on first launch

Milestones **A.03/F.03 — Verificado no escopo** for the observed native protocol
and chat controls; **D.02/E.01/F.05 — Parcial**. Broader roadmap acceptance
remains separate. Runtime identity is **028D / 0.9.29**
from `release.json`; document/container formats are unchanged.

Grok Build is a CLI-account connector inside ARK's Single Assistant and each
Team card. It uses the official ACP protocol and a role-owned reverse MCP
callback, with the actual model-visible tool catalog. It does not use a generic
live document bridge to bypass Team permissions or transfer a CLI subscription
into the existing xAI API connector.

The CLI keeps its authentication store. ARK isolates the process configuration,
denies external filesystem/terminal tools, preserves source revisions and host
permission checks, retains actual tool receipts after interruption and rejects
unsupported image inputs. No new runtime turn/token budget or cloud fallback
is introduced. The exact SDK-MCP capability and CLI model are negotiated.

The chat panel starts open when no visibility preference exists. Closing or
opening it through the actual control saves that choice for later starts;
the design and document format are unchanged.

## Observed verification and delivery receipts

- Grok Build 1.0.52 advertised SDK reverse MCP, four real model IDs and current
  model `grok-4.7`; image input was false. This probe sent no prompt or browser
  request. Early session probes rejected before any model prompt.
- With the operator's CLI login, the real runtime accepted a no-prompt session,
  initialized and listed the role-owned SDK MCP catalog, and returned the exact
  effective profile with all three isolation flags false and only
  `GrokBuild:use_tool` enabled. Actual rescan confirmed empty skills, no enabled
  external plugins and the exact Ready/enabled role-owned MCP catalog.
- The isolated `[permission]` configuration denies filesystem/shell/edit tools
  and permits only exact `MCPTool(ark__<authorized-tool>)` entries. The stdio
  runtime does not apply the root CLI permission arguments. Exact role schemas
  are supplied with the prompt; the finalized toolset rejects native tool guesses.
- Real Grok `grok-4.7` read-only authoring reached `agent_onboard` / `doc_info`
  at revision 0. A separate scratch trial called `doc_apply` once with
  `expected_revision: 0`, then `native_inspect`: revision 1, one feature, valid
  OCCT 8.0.1 B-rep with one solid and six faces, 480 mm³ volume, 416 mm² area and
  bounds `[0,0,0,10,12,4]`. Both terminal replies were accepted. Usage was
  unavailable; no cost or general design-quality claim follows.
- Two real Focused read-only Team trials confirmed the `reviewer` callback
  identity and zero writes at revision 0. The final observed role was Idle with
  one turn and an explicitly completed task, but the global goal remained
  **Needs input**, `goal_declared: false`, with zero unresolved errors. Idle was
  not treated as global completion. The opt-in live helpers are in
  `tests/assistant_acp_tests.cpp`.
- Native protocol tests cover real host callbacks, filtered tool discovery,
  read-only/scoped roles, complete messages, interruption, cancellation,
  retained receipts, steering and inspection before resumed writes.
- UI tests exercise CLI account/model selection, foreign-setting reset,
  per-card isolation, persistence and the first-launch chat visibility control.
- Windows native build and the final focused connector/ACP/Team/UI checks passed
  **4/4**. An earlier full native/Studio checkpoint passed **132/132 in 291.51s**;
  the subsequent live CLI probe exposed full registry IDs and legal nested
  request-ID reuse, which were corrected before final distribution.
- Subsequent real model trials exposed CLI watcher control responses and
  ignored stdio command-line permission flags before successful authoring.
  Ten failed model-prompt attempts reached no host callback: six unexpected-ID
  rejections, one unclassified non-end-turn result and three explicit cancelled
  terminal results. Two cancellations included an observed denied ARK permission
  request. All failed attempts retain unknown usage/cost.
  The complete observed series was 14 submitted prompts: ten diagnostic
  failures, one successful read, one successful box and two successful Team reads.
  Typed watcher acknowledgements trigger complete discovery revalidation;
  pending tool calls and terminal replies remain parked until the proof passes.
- The first full run had one visual measurement failure: the open chat reduced
  viewport height and the fixed crop excluded actual contact-shadow pixels.
  The adaptive crop retains the requirement for four distinct shadow modes.
- Final full-suite, authenticated scratch authoring, hosted Windows/Linux,
  relocated package and checksum results are recorded in the
  [028D release verification receipt](https://github.com/CenturyMesh/Ark/releases/download/v0.9.29/verification-028D.json).
  Development packages from the rejected early CLI checkpoint were retained
  locally and not published. The document format, Focused default and Parallel
  option are unchanged.

CLI authentication and provider eligibility remain necessary for inference.
