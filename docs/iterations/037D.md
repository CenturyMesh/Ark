# 037D - retain CAD contracts and establish an initial authoring checkpoint

Runtime 0.9.38 is defined by `release.json`. This addresses **A.03/A.04/D.02/D.04**.
Status: host contracts and coordinator **Verificado no escopo local**; real-model
design delivery and broader milestones remain **Parcial**. No drawing format
change is required.

## Reproduced defect

The generic request projection runs after conversation history exceeds 96 KiB.
Older completed tool results above 512 bytes were reduced to selected metadata.
That erased the rules and examples from a previously loaded `agent_onboard`
guide, including guides inside `query_batch`, after another tool response.
It also erased a sufficiently large semantic team receipt's `next_action`.
The original host history remained intact; the provider-visible request lost
the reusable authoring evidence. The 036A semantic progress tests exercised the
latest receipt, without detecting its loss after later reads.

A local C++ witness using the unchanged 036A production projection and a real
static solids guide reproduced both losses. With the same 171,188-byte history,
the baseline projection was 17,633 bytes and retained neither the rules nor the
next action. The corrected projection retained both in 33,058 bytes, preserving
the original host history exactly. This trades an incomplete smaller request
for retained required evidence; it is not a token/cost reduction measurement.
The witness and all intended regression transports use zero paid model calls.

## Changed behavior

- Keep one latest successful complete static guide per topic, with its actual
  build identity, arguments, rules, examples and command reference. A repeated
  guide does not repeatedly expand old provider input. Batched rows must match
  their actual query index and tool.
- Preserve explicitly selected guide fields as labelled historical subsets,
  even when `query_batch.fields` excludes identity metadata. Deduplicate each
  field; a metadata-only subset cannot replace a complete guide. Do not retain
  an unrelated batch inventory or fabricate omitted fields.
- Retain the latest relevant team action/roles/observed revision as historical
  evidence, excluding changing diagnostic accounting. Preserve original errors,
  source receipts and all user messages in host history.
- Keep retained tool facts at their original data trust level. Historical
  examples and observed revisions cannot bypass fresh successful document
  inspection, explicit `expected_revision`, scope checks or atomic rejection.
  An irreducible request still fails at the existing transport byte limit.
- Advertise every canonical command field in team authoring helpers, using
  shallow type hints instead of hiding `native`, `sketch`, `part`, `plane` and
  placement fields. Nested validation remains with the canonical server.
- Correct the lead's assignment tool names and add a coherent executable solids
  example: one editable circular sketch and a dependent native extrusion.
- Preload static overview, sketch and solids contracts for Studio writers before
  the first provider request. Specialist topics remain available on demand.
- For an empty Studio document in Parallel mode, retain other writers' accepted
  assignments and steering until the lead commits initial editable geometry.
  Read-only review may run independently. A parameter, group, empty sketch,
  preview or failed edit does not release those writers. Afterwards Parallel
  proceeds with current-revision inspection and unchanged atomic write guards.
  Ending the lead turn early reports an unfinished checkpoint without silently
  continuing a model. External core teams opt into this gate explicitly.
- Allow Studio construction steps with up to 128 commands, 32 created features
  and 64 placements, so related parameters, profiles, native operations and
  occurrences can form one atomic step with one Undo. Core defaults remain eight.
- Preserve the owned sketch validation cause in a dependent native-profile
  failure, including invalid ellipse radii, instead of reporting only that a
  named profile is invalid. Geometry tolerances and acceptance are unchanged.

Focused stays the default and Parallel remains optional. No new turn/token
execution budget, automatic CAD write, model change or cancellation is added.
User drawings, sessions and provider credentials are not included in the code
graph, test fixtures, commits or package.

## Real-model fresh-document pilot

One isolated real-provider pilot used three configured `gpt-6.1-sol` / `xhigh`
roles, actual `AgentTeam` and `AgentSession`, and the Studio role instructions
from source `1e79093`. It started at revision zero, without loading a drawing.
Initial request checks confirmed the preloaded contracts and complete shallow
command fields before the provider call. A five-minute host test window ended
the experiment; this is not a product turn/token budget. The harness omits the
GUI dispatch/render loop and price refresh, so this is a provider/executor test,
not an end-to-end interactive latency measurement.

**The pilot failed its initial coherent-concept criterion.** First visible
native geometry appeared after 92.199 seconds. At 300.193 seconds there were
two distinct visible native outputs, a solved assembly and six valid native
producer definitions. Intermediate producers are not six completed components.
The criterion required at least four distinct visible native definitions and
eight visible occurrences/outputs; the goal was not reported complete.

The provider reported 1,769,064 tokens across 40 responses (1,756,545 input and
12,519 output). Two in-flight responses were cancelled and lack final usage,
so this is a lower bound. All 42 attempted provider calls, three rejected tool
operations and the failed outcome are counted. An invalid ellipse initially
hid its radius error behind a generic dependent-profile failure; two other
edits rejected on revision conflicts. The eight-command Studio bound fragmented
related construction. The subsequent checkpoint gate, larger atomic batches
and exact profile diagnostic address these observed causes, but have not had a
second paid trial. No additional paid run was started to validate them.

The brief requested a first coherent editable concept rather than the earlier
full detailed design. Consequently the two sessions do not establish matched
token savings, a speedup ratio or successful design delivery. Raw provider
receipts, the isolated drawing and display snapshot stay private and are absent
from repository exports and packages.
