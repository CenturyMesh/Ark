# 025B — viewport visibility dock and selected-source drawings

Milestones: A.01/A.03, B.01/B.05. Status: **Verificado no escopo** for the local checks below.
The previous 024B preview is preserved. Runtime identity comes from `release.json`;
this UI change does not introduce a new `.ark` source or container format.

## Interaction

A floating OpenGL dock sits at the bottom centre of the design viewport. Its
code-native icons have active illumination, hover feedback and tooltips. The panel
background is 75% transparent (25% opacity); icons and labels stay legible:

- **Planes** hides construction planes/datums or shows all of them, including
  individually hidden datums. It does not alter authored references.
- **Sketches**, **Grid** and **Edges** change display state independently.
- **Fit** frames the document.
- **2D drawing** opens sheets bound to the selected part definition or container.
  A missing sheet shows an empty state for that source. **New sheet** offers that
  specific source and requires an explicit human action. It never creates a
  drawing merely because the user selects an object or opens the drawing view.

Container rows retain their existing expand/collapse behavior and now provide
visible selection context. Selecting a body clears the container context.
Parts/Assemblies in the drawing view return to the complete sheet library;
Design / 3D or Escape returns to the same modelling viewport.

The dock consumes its background clicks, takes precedence over model controls
behind it, adapts to the Assistant viewport and avoids the navigation compass.
During active edits the drawing shortcut is disabled. Existing drawing source
validity, stale-measurement and explicit-refresh contracts remain unchanged.
Agents still author manufacturing drawings only on explicit user request.

## Verification

`studio-viewport-dock-ui` and its compact variant exercise actual pointer input,
display-only revision/source preservation, restored hidden datums, viewport bounds,
part/container sheet selection, missing sheets without implicit creation, explicit
selected-source creation and the Assistant layout. Captures and completed checks
are recorded in `docs/verification-025B.json`; test definitions alone are not proof.

This is local UI evidence. No manufacturing qualification, new drawing geometry
domain or general performance improvement is claimed. Keep the draft unmerged
until user testing.

Windows x64 Release (LLVM-MinGW clang 23.1.3 UCRT, OCCT 8.0.1) passed
**127/127 tests in 256.46 seconds**. Actual captures were inspected at both
UI sizes, including the transparent dock over geometry and the Assistant layout.
The isolated `025B-test1` preview passed its dock workflow with packaged dependencies.
No user project is included. Hosted CI and manual acceptance remain separate gates.
