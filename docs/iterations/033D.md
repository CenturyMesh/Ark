A.04, D.02 and D.04. A.02/B.04/E.01 retain checked rollback, assembly custody
and source/contract compatibility. Document formats and geometric authority

## Contracts

`doc_preview` reports `candidate_budget_bytes`, `candidate_additional_bytes` and
the allocation scope. The unchanged 128 MiB retained-allocation limit is based
on actual packed storage, not a hypothetical expanded JSON representation.
Unshared native metadata is retained as an exactly verified JSON byte sequence,
with system lossless compression on Windows, and decoded lazily. Other platforms
retain the verified sequence without the Windows codec. A failed metadata
roundtrip retains the original owner. Producer B-rep, topology, provenance and
float64 display channels are unchanged. The Windows codec is loaded explicitly
from System32; no downloaded module or persisted compressed document format is
introduced.

Additional display buffers are released only after positions, normals and indices
match the retained native channels byte for byte. Transfer, snapshot, refresh and
publication materialize those same channels without running feature geometry.
Lazy expansion is charged again at serialized tool boundaries. Four-candidate
retention, expiration and producer validation remain unchanged. This is not a
process RSS ceiling or a promise that every candidate fits.

For an owned candidate, explicitly request
`doc_apply{candidate_id,expected_revision,refresh_candidate:true}` or its
`team_apply_step` equivalent after inspecting the current revision. The host
uses the existing dependency-scope refresh, evaluates the original unchanged
recipe and checks, retains the result, then publishes in the same serialized
operation. A failed refresh does not write. A direct stale apply still rejects.
Native/mesh inspection checks with audited feature selectors and `eval_expr`
join the refresh scope and run again. Other checks, implicit occurrence selectors
and unsupported recipes require a fresh explicit preview. DFM proposals require
a fresh explicit comparison and cannot use this shortcut.
`team_apply_step{...,release_reservation:true}` releases only the caller's owned
window after a measured successful commit. There is no TTL extension or rebase.

Team status, onboarding, preview and apply calls default to compact responses,
including status/onboarding reads inside `query_batch`;
explicit full/design modes remain available. Writable team aliases refer to
the canonical `doc_apply` command discovery; runtime operation/count/discipline
validation remains unchanged. Read-only preview discovery retains its complete
command schema. Completed tool history is projected once it exceeds 96 KiB and
the projection reduces the actual serialized request. Original task/role text,
images and host receipts are retained. Projection still requires current
inspection before another write. This changes request representation, not
agent turn/token budgets; Focused remains default and Parallel optional.

`team_context.roles[].request_context` reports serialized byte categories and
request counts. Successful context reads retain bounded numeric snapshots in the
project activity ledger; saving preserves them without copying prompt content.
HTTP request measurements cover Responses, Chat Completions and Messages wire
forms; unavailable measurements are explicit. Provider token receipts remain
separate. Byte reductions on a
synthetic fixture do not establish live model cost or design-quality gains.

`team_send{kind:"assignment",scope:{ids,expected_revision},...}` also supports
read-only recipients. Scope supplies measured context and grants no write
permission. `object_context` unknown-type diagnostics list valid types present
in the document.

`bom_inspect{ids:[feature IDs/names],...}` paginates inside the selected counted
definitions and retains the complete snapshot digest. `bom_review{ids:[...],
expected_revision,scope,fastening_review,pending_notes?}` requires those selected
items to have been read at the current revision. Its `global_review:false`
receipt does not replace or satisfy the global BOM completion gate. Omitting
`ids` retains the complete current-revision inspection and identity requirements.
Concept/detailed requirements and manufacturing qualification are unchanged.

## Verification

Windows Release focused verification passed **12/12 native** and **10/10
portable-core** registrations. Studio, CLI, MCP and the native worker compile;
generated release identity passes. The [receipt](../verification-033D.json)
records source/artifact hashes, exact registrations, limits and corrections.
These are focused groups, not full-suite or hosted-CI acceptance.

The public request fixture retains 146,498 bytes of original host history while
the projected wire input is 15,977 bytes; the standalone schema is 126,435 bytes.
For the same writable role, canonical command parameters occupy 24,507 bytes
and the compact alias 3,756 bytes. These measure different request components;
they are not token counts or a measured live-provider saving. Native and portable
team regressions pass 391 assertions, including saved request-context snapshots.

Native checks also cover exact checked refresh, dependency rejection, one-step
undo/redo, retained producer enrichment, transfer/materialization and unchanged
geometry on failure. Storage checks compare every value and mesh channel,
exercise concurrent lazy decoding and verify Windows lossless compression.

Initial validation rejected unsupported inspection checks and caught deferred
display bodies reaching refresh reuse before materialization. The audited check
scope and refresh materialization were corrected. Excess string capacity and
compressor output-bound handling were corrected, along with test-harness
response envelopes and activity-recording setup. Final results are fresh runs
after those corrections. Synthetic fixtures contain no user projects/sessions.

Linux execution, full suites, hosted CI, distribution/OTA qualification and live
model quality/time/cost comparisons remain outside this local verification.
