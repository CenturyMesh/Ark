# 027D — Ollama tool-schema compatibility and public downloads

Milestones: **A.03/D.02 — Verificado no escopo** for the adapter regression and
local Windows runtime; **F.05 — Verificado no escopo** for refreshed public packages.
Broader roadmap milestones remain **Parcial**.

The local Qwen GGUF backend rejected the first team request with HTTP 500:
`JSON schema error at #: properties must be an object`. Five discovered
no-argument tools use valid object schemas without a `properties` member.
Ollama's GGUF tool renderer requires an explicit empty property map.

The Ollama Chat Completions adapter now adds `properties: {}` only when the
root object schema omits it. Existing properties, required fields, extension
policies and canonical MCP discovery remain unchanged. Other providers retain
their original wire schemas. Revision checks and atomic CAD publication are
unchanged; the adapter does not remove tools or relax authoring validation.

The numeric runtime advances to **0.9.28**, with iteration identity **027D**
from `release.json`. The document/container format is unchanged. Earlier
published versions and user documents remain preserved.

## Evidence and limits

- The original five schemas were inspected through standalone MCP discovery.
- A minimal real request to the installed Qwen model reproduced HTTP 500.
- A request with the explicit property map reached actual prompt processing,
  but the initial high-effort diagnostic exceeded its 90-second HTTP test
  window. It is not a successful completion or CAD-authoring result.
- A regression exercises the full discovered catalog, preserves every declared
  schema constraint, verifies canonical discovery is unchanged and checks
  that other providers keep their original schemas.
- Windows x64 MSVC Release compiled successfully. After recovering free disk
  space, the full native/Studio suite passed **129/129 in 219.84 seconds**.
  The first execution encountered insufficient disk space; native writes and
  catalogue setup rejected. These resource failures are retained separately.
- The corrected minimal real request with thinking disabled returned HTTP 200
  and a `kernel_info` tool call. The full-catalog scratch authoring trial timed
  out. In the reduced-catalog trial, actual inspection/onboarding worked, but
  two box writes omitted `native.op` and rejected atomically at revision 0;
  that trial subsequently timed out. No completed autonomous CAD result is
  claimed for the installed model.
- The Windows ZIP inventory retained all required runtime/dependency notices,
  included no user drawings/settings, and passed the relocated local-model UI
  workflow at 1366×800. Its captures were inspected.
- The local Linux build completed but its test transport failed while the
  Docker backend and host disk were under resource pressure. A fresh hosted
  [Windows/Linux package workflow](https://github.com/CenturyMesh/Ark/actions/runs/38613566546)
  at source commit `d5f3610` passed **95/95 Windows native tests** and
  **93/93 Linux native tests**, plus relocated Linux package verification in
  a clean Ubuntu 24.04 container without the SDK.

This correction resolves the reproduced schema rejection. Model inference
latency, failed model-authored operations and general autonomous CAD quality
remain separate limits. The [artifact receipt](../verification-027D.json)
records exact archive hashes and the separate local/hosted qualification.
The public prerelease is [027D / 0.9.28](https://github.com/CenturyMesh/Ark/releases/tag/v0.9.28).

No runtime agent turn/token budget, cloud fallback, geometry tolerance change,
general model-quality claim or manufacturing qualification is introduced.
The separate team-recovery diagnosis in `HANDOFF_026D.md` remains open.
