# 051A - compressed derived section and container compaction

Runtime 0.9.52 and the iteration identity come from `release.json`. Phase **A**
(trust) is the principal focus. Milestones **A.02**, **A.04** and **A.05**
remain **Parcial**.

## Observation

A 299-feature hand design (Team session, 050B) saved as a 190.8 MiB `.ark`. Its
authoring was 1.15 MB. Read-only measurements on a copy:

| What | Size |
|---|---|
| Authoring payloads | 0.95 MiB |
| Saved-geometry cache (`ark_derived`, 294 entries) | 126.8 MiB, at its 128 MiB limit; 3 bodies omitted |
| Free SQLite pages left by earlier saves | 62.1 MiB |

Inside each entry the B-rep is OCCT text encoded as base64 (71.2 MiB in total),
and the topology table lists every earlier reference name; 79% of its 162,633
rows are `obsolete`, only 22,839 of them unique. Successive feature bodies
repeat most of their predecessor's geometry.

Compressing the same entries (Python zstd 1.5.6 / zlib, same machine):

| Option | Stored |
|---|---|
| zlib-6 per entry | 27.0 MiB |
| zstd-9 per entry | 24.1 MiB |
| zstd-9 per entry with a trained dictionary | 24.7 MiB |
| zstd-9 per entry, base64 decoded first | 16.6 MiB |
| One zstd-6 frame with long-distance matching, base64 decoded | 4.9 MiB (0.26 s, decode 0.05 s) |
| Delta against the most similar entry (B-rep only) | 4.0 MiB, chains up to 20 deep |

OCCT's binary B-rep format halved the raw text and parsed four times faster,
but after compression it saved only about 15%. B-rep identities and
`@ark.<kind>.<sha256>` reference names are SHA-256 of the B-rep text, so a
format change would make existing references obsolete. It was not adopted.
Dropping obsolete references was not adopted either: compression already
reduces the topology from 55.0 to 1.4 MiB, and they carry the explicit
"B-rep identity changed" rejection.

## Change

- The derived section (saved geometry and 049A baked frames) is one Zstandard
  frame over every entry in document order, level 6, long-distance matching,
  window up to 128 MiB, content size and checksum. Canonical base64 JSON
  strings of at least 1024 characters travel as decoded bytes. Rows are named
  `pack1.<manifest>.<index>`, at most 16 MiB each, with their SHA-256. The
  manifest covers keys, lengths and per-entry SHA-256 and is checked again
  after decoding. Entries are reproduced byte for byte.
- Delta chains were measured but not adopted: the single frame compressed
  better and needs no base selection, chain limits or re-encoding of dependants.
- Capacity: 64 MiB per entry, 256 MiB decoded, 128 MiB compressed, 8192
  entries. A pack over its stored capacity keeps the document-order prefix that
  fits; the save receipt counts the omitted tail. The container version stays 2.
- A save keeps an intact pack whose manifest is unchanged instead of
  recompressing it. Legacy per-entry rows still load; the next save writes a
  pack.
- Compaction: when a committed incremental save leaves at least a quarter of the
  file and 1 MiB free, `VACUUM INTO` writes a sibling copy. It is reloaded with
  the checked reader and must match the committed authoring hash and derived
  entry count before an atomic replacement. Otherwise the committed save stays.
- Receipts: `saved_geometry.encoding/stored_bytes/stored_capacity_bytes`, a
  `container` object, and `derived_geometry.container_encoding/stored_bytes/
  decoded_bytes` on load. Studio's partial-save status no longer quotes a size.
- Zstandard 1.5.7 is vendored unmodified (BSD alternative), with provenance,
  notices, About text, package licenses and SBOM entry.

See [formats](../FORMATS.md) and [container](../DOCUMENT_CONTAINER.md).

## Verification

Status: **Verificado no escopo local**, MSVC 2022 with the patched OCCT 8.0.1
SDK (`install-msvc-ark-offset-001`, patchset verified by CMake). GitHub Actions
and distribution were not run.

On copies of the user's design, with an isolated native cache and
`LOCALAPPDATA` for each run (051A `ark-mcp`):

| Step | Result |
|---|---|
| Open the 050B file, cold cache | 46.2 s; 294 entries staged from per-entry rows |
| Save in place | 4.6 s; 297 entries (152.9 MB decoded) in a 5.18 MiB pack; compacted 190.8 MiB → 6.1 MiB |
| Save again, unchanged | 3.0 s; pack kept, no compaction |
| Open the 051A file, new cold cache | 34.4 s; 297 entries staged, 0 discarded |

`doc_info{detail:"design"}` after the two opens is identical for 296 of 299
features. The three bodies that the 050B file had omitted differ only in
`volume_mm3`, by at most 2.9e-11 mm³: they were evaluated from authoring in the
first open and restored from saved B-rep text in the second. The open-time
difference includes those three bodies and is not a like-for-like speed claim.

Baseline: the retained 050B `ark-mcp` ran the same sequence on the same original
bytes with its own cold isolated cache. One sample each, same machine:

| Step | 050B | 051A |
|---|---|---|
| Open the 050B file | 47.1 s | 46.2 s |
| Save in place | 7.6 s, `partial` (3 bodies, 19.8 MB omitted) | 4.6 s, all 297 bodies, compacted |
| Unchanged save | 3.5 s | 3.0 s |
| File after the saves | 190.8 MiB | 6.1 MiB |

Compatibility: 050B opened the 051A file, discarded the derived section
("ARK derived payload checksum/identity mismatch") and evaluated all geometry
from authoring in 115.3 s. Against the 051A open, 191 volumes differ by at most
4.5e-11 relative and 60 bounds by at most 1e-7 mm. This is the existing
difference between a recompute from authoring and the session's saved geometry,
not a change made by the pack.

Tests: `derived-pack-051a` (130 checks): exact round trip with canonical,
non-canonical, short, unterminated and binary payloads; cross-entry compression
despite base64 misalignment; 19 hostile or damaged frames and bodies; capacity
tail; legacy rows and migration; mixed, gapped, renamed, digest-damaged and
missing-chunk sections discarded with authoring intact; 16 MiB row split;
compaction, no compaction for small edits, and a replacement blocked by an open
handle on Windows that keeps the committed save without a staged file.
