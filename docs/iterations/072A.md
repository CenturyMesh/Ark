# 072A — Growing documents and retained edits

Technical version **0.9.73**, phase **A**. Addresses **A.02/A.03/A.04/B.01/B.02/D.02/F.03 — Parcial** pending final local validation and packaging.

The fixed 128 MiB candidate threshold prevented retaining a valid geometric
preview. Separate 4 MiB authoring/history and 512-node journal quotas could
reject subsequent edits even when the machine had available memory. These
editing quotas are removed. The newest validated candidate remains retained
above the adaptive soft cache target; older uncommitted proposals may be evicted.
Source revision, candidate ownership, expiry, native validation and explicit DFM
acceptance continue to govern publication.

History grows without automatic pruning or forced compaction. Indexed ancestry
and visited IDs replace fixed traversal/replay counts. Receipts and the history
dialog show actual usage without a percentage of a discontinued quota. Explicit
archive-backed compaction remains available separately.

SQLite container v3 removes the physical metadata constraint and signals when
a file needs the newer reader. Compatible small files keep v1/v2; v3 files need
072A or later. The semantic model versions, canonical codec, geometry and
history identities are preserved. Available-memory checks protect external
decoding and repeated-reference expansion before allocation. Optional derived
caches and transport/domain-specific limits remain separate.

Detailed contracts and compatibility: [growing documents](../GROWABLE_EDITING_072A.md).
No user drawing is a fixture or part of the distribution. Explicit history
compaction remains a separate operation.

## Verification

The final core passed all **198 native/script test contracts**. The broad run
passed 197/198; its remaining legacy test expected the removed 128 MiB eviction.
That expectation was replaced with newest-candidate retention plus stale-source
rejection, and the targeted recheck passed 71 workflow checks. Core production
bytes were unchanged between those runs.

The candidate suite passed **65 checks**, including a real 129 MiB retained
allocation, zero/small targets, transfer, allocation-failure rollback and native
DFM acceptance. The large-document suite passed **36 checks** with 5,897,587
logical bytes, three distinct embedded PNG assets and exact source/geometry
round-trip. The fixture retained semantic version 39. History completed **560
edits and 568 final nodes**, retaining the original 512 IDs/deltas, undo/redo,
reopening and early-branch restore.

Container tests passed values above 16 MiB, 8,300 slots, v1/v2 upgrades, replay
of shared branch ancestry, a physical file above 256 MiB, blocked migration,
corruption and explicit insufficient read headroom. Existing archive-backed
compaction/migration tests passed on synthetic fixtures only.

Initial harness issues (C++ name lookup and JSON field-order comparison) were
corrected before final validation. All **4 affected Studio suites passed**: history, archive-backed compaction,
recovery and async authoring. The actual history dialog shows 527 retained
nodes and selects the oldest recorded edit beyond index 512. Its labels,
selection, details and restore control were visually inspected. The initial
Windows message-hook test probe missed the posted timer; direct read-only
observation in the existing test timer corrected that probe. Receipts are under `out/verification-072a` and
`out/release-068B/dev-tests-*.xml`. No general throughput improvement, arbitrary
project size or manufacturing qualification is claimed.
