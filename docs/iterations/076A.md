# 076A — Program hardening, run-scoped feedback and safer distribution

Technical version **0.9.77**, phase **A**.
**A.02/A.03/B.02/D.02/F.05 — Verificado no escopo local**; each milestone remains
**Parcial** outside the evidence below.

076A follows a review of PR #43 (066D) re-checked on the 075D source
(`4418507`, merged as `940cf99`). Every defect listed here was confirmed in that
source before it was changed. Most fixes have a test that fails on the earlier
code and passes now. Work was done in isolated worktrees, each patch was reviewed
independently, and the patches were integrated on top of `940cf99`.

## Parametric programs (B.02/A.02)

- **Crash on deep expressions.** About 2040 unary `-` or `!` characters, which
  is still under the 2048-byte expression limit, overflowed the stack and ended
  `ark-mcp` with `0xC00000FD`. The same validator runs when a `.ark` loads.
  All recursion levels now share one 64-level nesting budget, and deeper input
  rejects with a typed error. The repro returns normally on 076A; the 066D
  binary still overflows.
- **Non-finite values.** `assert:"1/(a-b) > 0"` with `a==b` used to pass and was
  reported as satisfied. Every computed value must now be finite, or the run
  rejects with `PROGRAM_NONFINITE`. `?:`, `&&` and `||` evaluate lazily, so
  guards such as `x!=0 ? 1/x : 0` keep working.
- **Static names.** A misspelled identifier in a branch not taken for the
  current values used to pass `validate`. Identifiers, builtin arity and `set`
  targets are now resolved lexically, including untaken branches and functions.
  Loading a document does not re-run name resolution: an older stored program
  with such a typo still opens, and rejects when it is configured.
- **Provenance.** `program.bind` used to check only that the owned names
  existed. A batch must now contain exactly the compiled commands, contiguous and
  directly before the bind, and nothing else in the batch may touch that
  namespace (`PROGRAM_PROVENANCE`). The `ParametricDesigner` role may publish
  only verified compiled blocks, plus clear/detach and its own variant steps;
  outside upserts, including those riding on `variant.*`, reject. Namespaces are
  not assigned per role.
- **Validation cost.** Bindings are fully validated on load (including undo,
  redo and iteration restore), on bind and on save. They are no longer
  re-validated on every in-memory serialization or clone. Local benchmark with
  8 bindings of about 112 KB and an unrelated `param.set`, alternating base and
  patched binaries on a shared machine:

  | Measurement | Before (ms) | After (ms) |
  |---|---|---|
  | `doc_apply`, no history journal | 184.9 / 180.7 | 44.5 / 38.3 |
  | `doc_apply`, with history journal (n=10) | 659 / 657 | 361 / 363 |
  | `documentToJson` | 34.0 / 34.8 | 9.3 / 6.9 |

  These are local measurements, not a general performance claim. Most of the
  remaining cost with the journal is the journal's own serialization.
- **Parameter kinds.** Boolean parameters, numeric `choices` and text choices.
  `{@name}` inserts a chosen text, for example a material name. Bindings that use
  a new kind require conditional document version **60**. Numeric-only bindings
  keep their earlier version, and removing the last typed binding returns to it.
  Version 61 rejects as a future format.
- **`.arkprog` exchange.** `export` writes the installed source and its SHA-256
  as canonical JSON. It never overwrites unless asked, and it leaves the
  document and revision unchanged. `validate`/`prepare` accept `program_path`.
  File I/O stays in the tool; the language still runs no file, script or
  network operation.
- **Context graph.** Bindings are indexed as `program:<namespace>` nodes, with
  `owns` links to their objects.
- **Not implemented.** Programs do not emit `assembly.add` or `mate.add`: mates
  have no stable names, so ownership, dependants and reference rewriting cannot
  be guaranteed.
- **Studio.** The Parametric HUD has a **Programs** view. Every declared
  parameter has a row, and changes are staged. **Apply** runs `configure` and
  then `doc_apply` as a human transaction on the CAD worker path. Typed
  rejections leave the document unchanged. Detach and Remove ask for
  confirmation. A value typed while another writer committed is not staged.

## Assistant and team feedback (D.02)

- **Feedback gate.** With Claude Code, runs often ended "Interrupted" with
  "Claude Code omitted required tool feedback after its reminder".
  - Cause: the Single assistant uses one actor id for every conversation.
    Receipts carried the oldest 64 unrated rows of the whole document, and all
    three connectors required them. There was a single reminder, and every read
    after it added another required ID.
  - The gate now covers only the actions created in the current run. Older
    rows are non-blocking backlog.
  - A reminder repeats only while this run's unrated count falls, so the loop
    always ends, without a turn or token budget.
  - A Single run that still has unrated actions ends with its reply and a
    "Feedback pending" status instead of an error. The missing feedback is kept
    in `AssistantResult::feedback` and in benchmark rows (`feedback_pending_count`,
    `accepted_with_feedback_pending_count`).
  - Team goal completion still blocks while a teammate has unrated actions from
    this team run (`teammate_unrated_feedback`).
  - Studio declares `actor.run`. Ratings of another run's rows are labelled
    `same_actor_other_run`. `run` is stripped before the history journal, so
    saved files keep their format.
  - `tool_feedback` errors name each failing item, and batches stay atomic.
- **Reasoning.** Team reasoning is carried on the event that produced it.
  Truncation keeps UTF-8 characters whole. Reasoning is cleared on a new or
  loaded document, iteration restore and STEP import. In an Error row, the host's
  error text is drawn before the provider reasoning toggle.

## Studio (A.02/D.02)

- **Chat dock DPI.** The minimum and normal widths scale with DPI, but the
  viewport reserve did not. At 144 dpi and 1280 px, the normal and expanded
  widths were therefore both 540 px. Expand is now disabled when it cannot
  widen the dock. The stored width round-trips exactly. Checks run at 96, 144
  and 192 dpi through a self-test override.
- **Review blockers.** The control is shown with agent cards collapsed.
  `studio-team-blockers-ui` and its compact variant pass; they had failed since
  065F.
- **Stack.** Studio keeps the 8 MiB reserve from `b63e93d`, through one CMake
  value (`ARK_STUDIO_STACK_RESERVE`). The session executor now uses a Win32
  thread that requests the same reserve explicitly. `studio-parametric-graph-ui`
  measures the main-thread high-water mark and fails above half the reserve.
  MSVC was not measured.

## Curved geometry (D.02; investigation remains Em curso)

[Design quality investigation](../DESIGN_QUALITY_INVESTIGATION.md):
- A 13-body probe gave identical tessellation and B-rep on 051A, 055D, 056C,
  066D and 075D. The faceted look is not a regression in those binaries.
- Curved edge outlines are now split by turning angle. For example, a hole that
  showed as 8 segments on a 5 m body now has 32. Surface tessellation is
  unchanged: restoring 0.12 rad for every size cost 3.7x the triangles and
  4.5x the time on a spline tube.
- Agent snapshots light curved bodies with vertex normals. Legacy
  extrude/sketch_cut and notched tubes stay hard-shaded, as in Studio. The
  receipt states the shading used.
- The sketch guide example uses `native_solid`. The solids guide has an "Exact
  curved forms" rule. The `equation2d` rejection explains why and names the
  exact curve recipes.
- A `turned_knob` program example revolves lines, cubics and an arc into one
  exact solid.
- No matched live model comparison was run. No change in agents' design quality
  is claimed.

## Distribution (F.05/A.03)

- **Signing.** Setup finds its payload before an Authenticode certificate
  table. It was checked with a temporary self-signed certificate; no trusted
  certificate was tested.
- **Integrity.** Setup opens itself once and uses that one handle for the
  footer, the SHA-256 check, extraction and `uninstall.exe`.
- **Install, upgrade and uninstall.** Uninstall holds `update.lock` before
  deleting. The new uninstall entry is written before the Inno entry is removed.
  Reinstall repairs a missing runtime. A damaged copy is moved aside and never
  deleted unverified. Downgrade needs `--allow-downgrade`.
- **Command line.** Inno-style silent switches no longer open a modal dialog.
  Folder paths are validated, and non-ARK non-empty folders are refused.
- **Disk space.** The check includes the temp drive.
- **CI and release hygiene.**
  - A `windows-installer` CI job builds ARK Setup in both configurations,
    renders the setup pages, and runs the process/payload/disk-plan harness and
    the engine tests, including a temporary test signature. It passed on a
    hosted `windows-2022` runner for PR #45 (Actions run 43435817912).
  - Packaging refuses a dirty tree unless `-AllowDirtyTree` is passed.
  - .NET `bin/obj` output is ignored.
