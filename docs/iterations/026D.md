# 026D — local Ollama agent selection

Milestones: A.01/A.03, D.01/D.02. Status: **Verificado no escopo** for connector/UI contracts; D.01/D.02 remain **Parcial**.

The Assistant menu now exposes **Local models / Ollama**. Installed-model
selection checks actual Ollama metadata before saving the connector. Each team
card can choose a separate local model, and its Settings uses the same selector.
Tool-less models reject; absent vision is retained as an explicit image gate.
The selected local provider is correctly labelled even while ChatGPT is signed in.

Global provider changes clear only inherited role model/effort overrides, and
reset an idle team's old connector configuration. Explicit card connectors and
the user's CAD document remain unchanged. Local inference uses the existing
validated assistant loop, without a cloud fallback or new run/token budgets.

The runtime identity advances to 026D / 0.9.27; source/container format is unchanged.
025B remains available as its original preview. Keep PR #11 in draft for user
testing. See [local model usage](../LOCAL_MODELS_026D.md).

Windows x64 Release passed **129/129 tests in 276.98 seconds**. Both UI
sizes were visually inspected, and the isolated preview passed its local-model
UI workflow. The actual Ollama catalog returned four installed model IDs.

Only `qwen3.5:2b` was used for inference. Both live scratch authoring trials
(full catalog and three tools) reached the eight-response test bound. The reduced
trial executed real inspection tools but omitted the native operation in two
writes; ARK rejected both with revision 0 and an unchanged scratch document.
The observed full-trial context was not truncated. This proves transport and
guard behavior, not autonomous CAD success. Larger models remain for user testing.
