# 021B — direct authoring, associative drawings and DFM proposals

Runtime `0.9.22`, principal phase B. The iteration addresses A.01, B.01,
B.02, B.03, B.05, C.03, D.02 and D.04. These milestones remain **Parcial**
outside the tested domains below. `release.json` is the source of application
identity; document version 36 is conditional on new drawing or extended
extrusion authoring, rather than on the application version alone.

## Direct human geometry

The selected saved profile or supported exact planar face exposes a viewport
extrusion handle. Its native candidate supports a numeric expression, reverse
direction, symmetric total depth and an associative `up_to_face` bound. The
bound uses an exact parallel planar B-rep face and requires full exact coverage
of the resulting cap. Incomplete, angled or curved limits reject without
substituting display geometry. Source and limit bodies remain separate physical
outputs for viewport, BOM and mass. See the [viewport workflow](../VIEWPORT_DIMENSIONS.md)
and [bounded extrusion verification](../verification-extrusion-bounds.json).

## Technical drawings

Persistent drawings link an explicit feature ID, exact B-rep digest, topology
digest and observed revision to orthographic views, exact planar sections,
semantic dimensions and caller-declared tolerances. A source change makes
derived measurements stale until an explicit revision-checked refresh. JSON
export retains derived exact curves; SVG and the Studio sheet workspace are
presentation/authoring surfaces. See [the drawing contract](../DRAWINGS.md).
B.05 remains partial: assemblies, full drafting standards, GD&T, hatching,
PDF/DXF drawing exchange and physical drawing qualification remain open.

## Agent DFM and visual feedback

`manufacturing_propose` evaluates explicit editable commands in an isolated
candidate and compares exact source geometry plus every current DFM rule under
the same declared process/material. It exposes regressions in other components
and unresolved evidence. A retained candidate requires a separate
`accept_dfm:true` commit with the observed `expected_revision`; no rule result
alone changes the document or qualifies manufacture. See
[DFM proposals](../DFM_PROPOSALS.md).

A read-only audit of the local in-product agent activity identified repeated
requests for Z-up/front camera control and one Studio viewport readback error.
Software `snapshot` presets now use Z-up and accept a bounded custom camera;
viewport capture reports actual render/readback errors and rejects a custom
camera on that live view. The private project ledger is not published. See
[snapshot camera contract](../SNAPSHOT_CAMERA.md).
